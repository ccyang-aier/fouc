## 通过的实际流程（逐条对应验收标准）

- **按 workspace/hash 寻址与秒传**：对象键为 `<workspaceId>/<sha256>`（path-style）。同 workspace 相同 hash 探测返回 `{action:'reuse'}`，重复 confirm 幂等返回 `created:false` 且 `asset.created` 事件与 graphile job 数量不变（仍为 1）。跨租户不泄漏：Alpha 确认 hash 后，Beta 对同一 hash 的探测拿到指向 `<betaWorkspace>/<hash>` 的全新上传授权，与未知 hash 的响应形态一致；两 workspace 各自独立对象（两个 key 分别 HEAD 可见）、各自可下载。
- **上传确认校验**：confirm 先 HEAD（Content-Length/Mime/ETag）再流式 GET 单遍摘要（SHA-256 主判 + MD5 对照非分片 ETag——HEAD 本身无法验证 SHA-256，必须读回内容）。哈希不符 / 大小不符 / 类型不符均：删除该键下对象（HEAD 复核 404）、不落库、不发事件，返回结构化错误码 `ASSET_HASH_MISMATCH` / `ASSET_SIZE_MISMATCH` / `ASSET_MIME_MISMATCH`；未上传即确认返回 `ASSET_OBJECT_MISSING`。
- **下载授权**：预签名 GET 仅对 `status='ready'` 资产、经 `expandRequestPrincipals`（P03 权限模块）确认的 workspace 成员签发；非成员/跨 workspace 请求 `ASSET_ACCESS_DENIED`，未知 hash `ASSET_NOT_FOUND`。授权 URL 方法参与签名（GET 授权不能 PUT、反之 403），PUT 600s / GET 300s 到期（1s 授权 + 2s 后请求实测 403）。
- **asset.created 原子且真实 S3 往返**：资产行插入与 `appendKnowledgeOutbox` 同一 `withKnowledgeTenant` 事务：① 调用方在 confirm 成功后抛错 → 行/outbox/dispatch job 全部回滚且对象保留可重试；② 队列 schema 缺失使 `add_job` 失败 → 资产行与 outbox 一并回滚。并发 confirm 经 `ON CONFLICT DO NOTHING` 收敛为单一 `asset.created`。
- **撤销**：软撤销（对象保留、`status='revoked'`）后下载、再探测、再确认全部拒绝（`ASSET_NOT_READY`）；撤销发布 `workspace.event(asset.updated)`；重复撤销幂等。

## 关键决策

- **键结构与秒传语义**：设计 §8.1 明确哈希寻址限定工作区内——探测/键/RLS 三者同以 workspace 为界，同 workspace 区分「已存在/新建」（秒传复用），跨 workspace 不区分。
- **下载授权语义**：设计文档未定义资产级 ACL，媒体块存于 Yjs 文档、服务端无资产→页面挂载表，故资产级授权 = workspace 成员 + asset 表状态；页面级 `authorizePageAccess` 属页面 API 边界（P03/B 层），不作为资产签发条件。
- **撤销为终态**：被撤销的 (workspace,hash) 拒绝再次上传/确认，防止成员用重传绕过禁用；重新启用属未来管理操作。
- **schema**：`asset.status` 枚举 `('ready','revoked')` NOT NULL DEFAULT 'ready'（行仅由确认路径创建，无 pending 中间态——预签名不落库，无孤儿会话记录）；`current.sql` 已重新生成，schema 测试补充资产生命周期断言。

## 明确边界

本任务为内部服务层（`permissions/mutations.ts` 风格：zod 严格输入、调用方持有租户事务、结构化错误码），不含 tRPC/HTTP 端点与发起者会话接线（U08/B 层）、`asset.created` 的运行时消费者注册（W04 视觉/转写 worker）、>5GiB 分片上传（契约上限 5GiB 单 PUT）、撤销的角色分级（当前任意成员可撤销，策略归 HTTP 层）与放弃上传的孤儿对象回收。
