## 逐条验收标准与真实观察

- **创建/回复/解决/重开/删除有独立生命周期**：创建 = 线程（`status=open`）+ 首条评论同事务落库，输入 `"  First observation  "` 落库为 trim 后值；回复按 `created_at` 升序（id 决胜保持全序）；解决 open→resolved、重开 resolved→open，重复应用当前状态为幂等 no-op（不发事件）；回复已解决线程报 `COMMENT_THREAD_RESOLVED`，重开是唯一回到 open 的路径。删除两条路径：作者删自己评论（非作者删除被拒 `COMMENT_ACCESS_DENIED`；线程最后一条评论删除时线程随之消失，随后对线程的任何操作报 `COMMENT_THREAD_NOT_FOUND`）；管理员（member.role ∈ owner/admin）删整个线程（评论经 FK 级联清除，普通 member 被拒）。管理删除后线程对原参与者不再可访问。
- **仅 comment+ 可写**：创建/回复/解决/重开均在操作事务内经 `authorizePageAccess(required='comment')`；view 级成员列表可读（返回 1 条线程）而全部五个写路径逐一 `COMMENT_ACCESS_DENIED`；comment/edit/full 三级各在独立授权子树上完整走通创建→回复→解决→重开（含继承与显式授权）。权限在事务内刷新：回收页（`deleted_at` 置位）上线程的读/回复/解决/删评论/管理员删线程全部即时拒绝，恢复 `deleted_at=null` 后同一线程立即可回复——无任何缓存宽限。
- **通知 Outbox 原子**：回复/提及在同一事务产生 `notification` 行（kind `comment.reply`/`comment.mention`，payload `{threadId, commentId, actorId}`，pageId 列指向来源页）+ `workspace.event` outbox 事件（复用既有契约：内层 `comment.changed` 与 `notification.created`，未新增主题类型）。同一事务可观测三件套：2 个 comment.changed + 1 个 notification.created。失败回滚零残留：服务写入成功后事务内抛错 → comment/notification/outbox（含 graphile 作业入队）计数与失败前完全一致；非法输入（空白正文、重复提及）同样零写入。收件人权限过滤：被提及但无页面 view 权限的成员、非成员、操作者本人一律不产生通知；参与者同时被提及只收一条 mention。
- **workspace 隔离**：Alpha 线程 id 在 Beta 租户事务中被 `comment_thread` 复合主键 + RLS 双重屏蔽——Beta 管理员（其 workspace owner）回复/删线程报 `COMMENT_THREAD_NOT_FOUND`，按 Alpha pageId 列表报 `COMMENT_ACCESS_DENIED`，Beta 事务内按 id 直查 thread/comment/notification 三表均为 0 行；同一外部用户在 Alpha 事务内因非成员被拒（deny 与不存在不可区分）。

## 关键决策

- 线程锚定页面：与 §3.2 `comment_thread(id, page_id, status)` schema 一致；blockId 锚点由 §4.6 的 CRDT `comment` mark 承载（N02），服务端不存不收 blockId。
- 提及为结构化 `mentions: uuid[]` 输入（服务端不解析 markdown），≤100 且去重拒绝；通知收件人 = 线程其他参与者 ∪ 提及者 − 操作者，再按「成员 + 可 view 该页面」过滤，mention 优先于 reply 合并。
- 管理员删线程 = workspace owner/admin 角色 + 至少 view 级页面授权（回收/不可见页面同样 fail closed）；作者删自己评论要求 comment 级（view 只读，删除亦为写）。
- 测试中 ACL 授权与 drain 全部先于评论事件完成：fixture worker 尚未注册 `workspace.event` 消费者（属 N03），此时 drain 会对该主题按设计永久重试。

## 明确边界

不含 tRPC/HTTP 路由接线（属后续 API 任务）、CRDT 锚点与侧栏（N02）、通知收件箱消费与已读（N03）、评论编辑（无 schema 列支撑，未在 N01 范围）。`comment.changed`/`notification.created` 主题类型已存在于 shared 契约，本次未改任何 shared 文件。
