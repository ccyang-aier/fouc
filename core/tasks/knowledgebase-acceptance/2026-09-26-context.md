## 架构（§9.6）

- **单一组装入口**：`assembleContext(pool, { workspaceId, userId, taskKind, query?, searchHits?, focus?, history?, budgetBytes? })` → `AssembledContext { taskKind, segments, usage }`。`segments` 按 §9.6 顺序：`rules`（固定规则+AI 方言格式说明）→ `outline`（页面标题路径 + 标题树逐项带 blockId）→ `neighbors`（焦点块+前后块，M02 `read()` 锚点切片，自带 `{#b:id}`）→ `retrieval`（H04 命中的权威索引正文，带来源腿标记）→ `history`。每段带 `text`（可直接进提示词）与 `bytes`（UTF-8 实际用量）。
- **不触网关**：检索腿以 H04 命中数组为输入（调用方 J04+ 先 `searchHybrid` 再组装），组装在 `indexedBlockAccessCondition` 谓词内回读 `block_index.contentMd`（自带锚点）；检索后失权/消失的命中按 `unavailableRetrievalHits` 如实剔除。焦点授权与检索回读共享一个租户事务快照。
- **焦点腿授权**：P03 `authorizePageAccess(view)` 唯一入口；deny/rebuilding/页面缺失 → 大纲+邻块两腿整体 fail closed（其余分段照常组装，测试 5）。焦点 blockId 不在权威文档（已删除）→ 仅跳过邻块腿（测试 4）。邻块 = 焦点 + 文档序前/后各一块（容器块也在 blocks 清单中，切片含嵌套锚点）。
- **预算口径**：UTF-8 字节（`Buffer.byteLength`，与网关/索引输入上限同量纲），默认 65,536。超限**仅**从检索腿尾部按命中名次整条剔除（不做中途截断——半条引用会诱发幻觉锚点）；固定段（规则/大纲/邻块/历史）永不截，检索腿清空仍超预算时以 `overBudgetBytes` 如实报告。剔除按渲染后字节精确计算（头部+条目+分隔符逐项累加），`truncated`/`droppedRetrievalItems` 分开计数。
- **引用校验**：`validateCitations(pool, { workspaceId, userId, citedBlockIds })` → `CitationVerdict[]`（首次出现序去重，上限 100）。可见性以 doc_state 权威文档为准：逐页 `authorizePageAccess(view)` + 解码 Y 树 + `createAiContext` 块清单——**未落 block_index 的布局容器块（index.mode=skip，如列表）同样可校验**（测试 3：`b-list` 无索引行但 valid，且经 `readPageBlockIndexRows` 证明确无索引行）。valid 附 `pageTitle` + 锚点剥除后的正文摘要（≤120 字符，与 H04 摘要同宽）。损坏正文解码失败按 fail closed 全部裁决 invalid。

## 通过的实际流程（逐条对应验收标准）

1. **规则→大纲→邻块→检索→历史顺序**：测试 1 五腿齐备，`segments.map(kind)` 逐项断言；大纲 titlePath 为根→本页标题路径（`['规则手册','氦闪研究']`），标题树逐项 `{blockId, level, title}`；邻块按文档序（焦点 `b-p2` 的 after 是二级标题 `b-h2` 而非下一段，验证真实邻接而非同型块）；检索条目带 pageId/来源腿/锚点正文；`assembledContextSchema.parse` 全程往返。`ask`/`edit` 任务族仅规则段措辞不同，其余段字节数逐段相等。
2. **预算超限从检索尾部截断**：测试 2 以真实 6 命中语料跑三个预算档：全量（truncated=false）→ `totalBytes-10`（恰剔尾部 1 条，保留集断言为完整名次序列的**前缀**，固定段字节与全量逐段相等，totalBytes ≤ budget）→ `1` 字节（检索腿清空、无 retrieval 段，规则/大纲/邻块/历史原样保留，`overBudgetBytes = totalBytes-1` 如实报告）。
3. **回答 blockId 引用校验与权限过滤**：测试 3 混合引用一次裁决：无权（读者引私有页）/有效（共享页，excerpt 为锚点剥除后的正文）/重复去重/不存在/已回收/畸形（`not-a-uuid` 原样回显）→ 五条 verdict 首现序逐一断言；所有者视角私有段与未索引容器块 valid、伪造块 invalid。测试 5 补检索后收权：读者以旧命中组装，全部命中被谓词剔除（`unavailableRetrievalHits: 2`），且读者主体集非空（剔除来自谓词而非身份失效）。
4. **结构化输出供 J 系列复用**：分段+来源标记落在共享契约 `shared/src/knowledge/contracts/ai.ts`（zod schema 驱动，前后端共用）；`retrieval.items[].sources` 取值域与 `hybridSearchSourceSchema` 一致（独立声明避免 contracts→search 反向依赖）。

## 关键决策

- **预算口径选 UTF-8 字节而非 token 估算**：与网关/索引输入上限同量纲、确定可加和、可按段精确报告；token 估算依赖分词器版本且不可加和复算。J04 接线时按模型档换算覆盖 `budgetBytes` 即可。
- **截断语义选「尾部整条剔除」而非「尾部截断文本」**：检索条目是可引用单元（锚点在块尾），截半条会制造模型引用不存在锚点的幻觉面；且整条剔除使「保留集 = 名次前缀」可被调用方直接推断。
- **无权/不存在/回收折叠为同一 `invalid`**：P03 惯例（三类拒绝不可区分）——引用接口若区分「存在但无权」与「不存在」会被用作块/页面存在性探测（模型引用 → 观察裁决即可猜测 ID）。
- **校验源选 doc_state 权威文档而非 block_index**：索引有滞后且布局容器块不落行（skip 模式），而邻块腿读的正是权威文档——校验源与上下文源一致才不会误杀模型合法引用；索引行仍用于检索腿正文回读（那里命中本就来自索引）。
- **taskKind 归并为 `ask`/`edit` 两族**：§9.4 的五个入口（划词/续写/侧栏对话/AI 块/长任务）对组装顺序无差别，仅规则段措辞分「回答引用」与「建议写回」两族；更细的任务差异留给 J04 的提示词层。
- **`focus.blockId` 缺省只组装大纲腿**：无选区/光标的任务（侧栏对话指向整页）不需要邻块；焦点块消失（并发删除）跳过邻块腿而非失败，大纲与检索仍可用。

## 明确边界

- **对话历史由调用方裁剪**：历史腿是固定段（不截断）；超大历史会顶爆预算并如实报告 `overBudgetBytes`，调用方（J04）应先按会话窗口截取。
- **邻块媒体派生文本**：邻块切片经 `createAiContext` 不带 `derivedByAsset`（与 H01 索引投影同一约定）；媒体块的派生文本（OCR/转写）进入上下文需先经 asset 装配，属后续真实需求出现时的扩展点。
- **常驻接线**：tRPC/AI 会话/MCP 对 `assembleContext`+`validateCitations` 的组合根注册与 J04 流式模型调用属后续任务；本任务交付服务入口与共用契约。
- **并发事实**：组装/校验各共享一个租户事务快照，但检索命中（调用方先前事务）与回读（组装事务）之间的收权/删除按「诚实剔除」处理（`unavailableRetrievalHits` / invalid），不做跨事务一致性保证——与 H04 回填同款语义。
- **引用裁决不区分失权原因**（见关键决策）；需要向用户解释「引用被剔除」时统一话术为「引用无效或已不可见」。
- 并行代理在途文件（`backend/server/src/modules/knowledge/import-export/`、`ai/tools/`）与本任务交付互不触碰；最终一轮 `bun test backend/server/src/modules/knowledge/ai` 40 项全绿时 tools 测试已由其所有方修复。
