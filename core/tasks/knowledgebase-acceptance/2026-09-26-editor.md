# E03 · Tiptap 编辑器 React 容器与状态

日期：2026-09-26。模块：`src/features/knowledge/editor/`（全部新建，15 个文件）与根 `package.json` 依赖；知识 API 网络层（`page-session`）复用 B04 `connectPageDocument` 与 B08 `createPageUndo`（零改动接入）。设计依据 §4 编辑器、§4.1 块模型、§5.1 文档生命周期、§10 工程结构（React NodeView 不进 shared，E05 前不做 NodeView）。

## 实现清单

- **`editor-state.ts`（纯函数）**：P03 `page.access`（action=view，一次往返返回有效级别）→ 四态 gate（pending/granted+level/denied/error）；`levelSatisfies` 级别序（view<comment<edit<full）；B04 状态机 → 同步指示视图（loading/local-only/syncing/synced/offline/error × label/hint/tone/busy）；`derivePageEditorView` 闭环决策：级别低于 edit 或 B04 终态 error → 只读（原因 below-edit / auth-failed），其余全相位（含离线）可编辑（§5.4）。
- **`page-access.ts`**：`page.access` 查询（键挂在 `pages` 段下，B06 acl.changed 事件天然失效），`usePageEditorGate` 输出 gate + 原始错误 + retry。
- **`page-session.ts`**：每页一个 B04 会话 + B08 撤销控制器的同生命周期 hook——endpoint 解析失败可 retry；状态携带 scope key，页面切换期间绝不把上一页（已销毁的）Y.Doc 渲染到下一页；订阅 B04 事件重读 `session.getStatus()`，组件从不持有第二正文状态。
- **`page-collaboration.ts`**：唯一 Tiptap 协作扩展——`ySyncPlugin(doc.getXmlFragment('default'))`（与后端索引器/协作服务的 PAGE_BODY_FRAGMENT 同名）+ `yUndoPlugin({ undoManager: B08.local })` + Mod-z/Mod-Shift-z/Mod-y 键绑定（y-prosemirror 自带 undo/redo 恢复选区）+ **历史协调插件**（见关键决策）。
- **`editor-surface.tsx`**：Tiptap 实例 = shared 注册表扩展（E01，`getSchema` 与 `knowledgeSchema` 同源，不自建第二套）+ E02 `createBlockIdExtension({ pageId })` + 协作扩展；`immediatelyRender: false` + `useEditor` 判空（SSR 安全）；`setEditable` 随派生视图模型同步；共享 schema DOM 输出的全量文档排版（标题层级/列表/待办勾选框/引用/代码/表格/callout/行内 marks，全部 design tokens）。
- **`page-editor.tsx`**：状态闭环容器——gate pending 骨架 / error 可重试 / denied 无权（不建会话不碰 IndexedDB）；endpoint 失败可重试；会话就绪前「正在打开文档」；就绪后挂 surface。
- **`editor-boundary-options.ts` + `editor-boundary.tsx`**：Client Boundary——`next/dynamic(ssr: false)` 按需加载编辑器 chunk（不进首屏 bundle、不服务端渲染），加载态为文档形骨架（role=status + sr-only 文案）。
- **组件**：`editor-toolbar`（撤销/重做为真实 B08 栈操作 + 栈事件驱动禁用态；格式组为 E04 诚实占位，aria-disabled）；`sync-indicator`（六态 pill，role=status 优雅播报，tone 色 token 化）；`readonly-banner`（below-edit 按级别区分文案 / auth-failed 错误横幅）。
- **接线**：`knowledge-page.tsx` 三行最小接线（选中页面 → `<KnowledgePageEditor scope>` 替换画布概览），随 U03 的 `selectedPageId` 落地（见边界说明）。

## 关键决策（含一个跨任务集成缺陷的修复）

1. **E02 × B08 × y-prosemirror 的撤销丢失缺陷（真实缺陷，已在编辑器内修复）**：E02 的 blockId 修复事务以 `addToHistory:false` 收尾（对纯 PM history 正确），但 y-prosemirror 把**整个 dispatch 批次的单次 Y 推送**标记为批次*最后一笔*事务的该标志 → 一切产生修复的块编辑（新建/拆分/合并/粘贴）整体逃出 B08 撤销栈（实测 `canUndo()=false`）。修复：协作扩展的历史协调插件在「用户内容变更 + 修复」同批时补一笔 meta-only 事务恢复标志（经 `appendedTransaction` 元数据识别批次根，纯修复批次如 onCreate 不入史）。
2. **selection-only 批次毒化撤销栈（同源机制）**：首次内容变更后 ySync 对**每次**派发（含光标移动/聚焦等无 step 事务）都推送空 Y 事务，而 Yjs 对任何被捕获事务清空 redo 栈 → 点一下正文就丢 redo、撤销按钮虚亮。修复：协调插件对无 docChanged 的批次补 `addToHistory:false`（与 PM history 对 selection-only 的忽略语义一致）；工具栏撤销/重做后用 `view.focus()`（DOM 焦点）替代 `commands.focus()`（会产生事务）。
3. **只读闭环的取舍**：级别低于 edit → 只读（横幅按 view/comment 分文案）；B04 终态 error（服务端拒绝同步连接）→ 停写并展示错误横幅（本地副本仍可读）；离线/local-only/syncing 全部保持可编辑（§5.4）。
4. **gate 用单次 `page.access(action:view)`**：allow 应答自带有效级别，一次往返同时决定「能否打开」与「能否编辑」，denied 即终态（B01 也会拒绝 WS），不建会话不碰 IndexedDB。
5. **页面正文片段名 `'default'`** 在编辑器侧以常量复述并注释指向后端 `PAGE_BODY_FRAGMENT`——该契约名理想上应上移 shared（本次所有权受限未动，见边界）。
