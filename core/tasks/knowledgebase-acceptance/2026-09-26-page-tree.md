## 通过的实际流程（逐条对应验收标准）

- **UUID 离线可建**：客户端随机 UUID 直接落库（createdBy 为服务端验证身份，契约拒绝 actor 注入）；同一 id 重复提交/不同负载冲突均按已存在处理，返回库存行，库内始终一行、首写内容不变。
- **ltree 子树移动**：移动节点在 withAuthorizedPageTreeMutation 边界内单事务更新 parentId/position/path，子孙 path 由 `newPrefix || subpath(path, nlevel(oldPath))` 单语句服务端推导；四级子树移动后逐行断言新 path 与 nlevel；根提升/降级保持「根无父、根 path=id、parentId IS NULL ⇔ nlevel=1」；子树全部行 aclRevision+1 且 outbox 产生 revision 匹配的 acl.changed。
- **分数排序**：base-36 规范键（6 位定宽整数 + 不以 0 结尾小数）+ BigInt 精确中点 `positionBetween(prev, next)`；afterPageId 相邻插入仅写新行、兄弟键零改动（前后快照相等）；40 次随机位置插入后 SQL `ORDER BY position` 与客户端代码单元序完全一致；连续 30 次追加键全序、去重、稳定；排序键耗尽（256 位邻差 1）与遗留非规范键（'a0'）触发仅该父节点兄弟集的局部均匀重排，外部页面位置不变。
- **回收恢复**：recycle 置 deletedAt 后 readMaterializedPagePermissions 返回 unavailable；真实调用 P02 rebuildPermissionSubtree 后回收子树叶级物化为空、effectivePageAccessCondition 谓词零命中（子树不可访问）；restore 清除标记并重算后三级页面全部重新可见。
- **禁止项**：祖先移入自身子孙（INVALID_PAGE_MOVE）、自父（契约 INVALID_PAGE_INPUT）、跨 teamspace 父子/回收父（INVALID_PAGE_PARENT）、谎报 teamspace（INVALID_PAGE_MOVE）、afterPageId 不属于目标父（INVALID_PAGE_PLACEMENT）、回收主体移动（PAGE_NOT_FOUND）全部在写库前拒绝且库内零变化；跨租户父子由 schema 拒绝（FK 23503 page_teamspace_fk 实测）。
- **失败事务回滚**：移动成功后调用方抛错 → 全部行（含 aclRevision）与 outbox 事件数回滚至快照；移动中途校验失败同验证零残留。

并发（4 连接真实竞态）：两个不同节点并发移入同一父 → 串行化后双双落位、键互异有序；同一节点并发移向两个不同父 → 无一失败，终态恰好一个一致树（父/路径/子孙前缀互相吻合）。

大子树：48 层主干 + 分支共 101 节点整体迁移，逐节点断言推导 path；90 级链原始插入被 schema 拒绝（见边界）。

## 实现要点与关键设计决策

- **排序算法**：position 字符集刻意取 [0-9a-z]——实测该实例 collation 为 en_US.utf8，混合大小写在 linguistic 排序下与代码单元序分叉（'aa' < 'aB' < 'b' < 'Ba'），仅小写+数字子集在 C/C.UTF-8/en_US( glibc/ICU) 下与 SQL 排序一致；定宽 6 位整数部分保证字典序=数值序，去尾零保证唯一规范形。中点用 BigInt 有理数精确计算（奇数和扩一位小数），严格落在开区间；唯一失败模式是超 256 长度 → 兄弟集均匀重排（36^6/(n+1) 间距）后重试。
- **并发语义**：全部树变更经 withAuthorizedPageTreeMutation 的 workspace 行 FOR UPDATE 串行化，兄弟读取在锁内进行，无 stale read；锁序沿用 P02 workspace→teamspace→page，与 fence/rebuild 同序无死锁。position 无唯一约束，正确性由锁与开区间中点共同保证。
- **两段式移动**：节点自身 parentId 与 path 必须同语句更新（分步会中途违反 page_root_path_depth 互斥不变式，实测触发）；子孙前缀推导为第二条语句且严格更深，规避 ltree `subpath(path, nlevel)` 越界抛 invalid positions（实测 offset==nlevel 即抛错）。
- **幂等**：create 以显式 id 幂等；move 重放收敛为 no-op（同父同键同路径跳过写库）；recycle/restore 天然幂等。no-op 仍会走 fence（P02 边界契约如此），代价一次可合并的重算。
- 服务为内部层：不接收 actor，注释声明 P03 须先以 authorizePageAccess 校验源子树/目标父至少 edit。

## 明确边界

- P03 路由层授权（source/destination edit、HTTP 错误映射）与 T02 数据库行页面、A02 tRPC 暴露不在本任务；越权移动的结构性防御（teamspace/租户/回收）已在服务层实测。
- **schema 物理深度上限（实测）**：`page_workspace_path_unique`（btree，workspace_id+path）在约 69 层报 index row size 2712 > 2704；`page_path_gist_idx` 自约 52 层起出现非确定性的 stack depth limit exceeded。故字面「百级深度」在当前 schema 下不可存储——百节点子树以 48 层主干验证，90 层插入被 schema 拒绝作为边界证据；超出上限的移动/插入以原始 pg 错误（54000/54001） surfaced，未包装为结构化错误码。schema/索引属数据库任务所有权。
- movePageInputSchema.operationId 仅校验不消费（离线重放靠自然收敛幂等）；不提供跨 teamspace 子树整体迁移与树读取/list API（验收为变更语义，读取归 API 任务）。
