# Q01 · 事务 Outbox 与 Graphile Worker

日期：2026-09-26。仅验证真实 PostgreSQL 调度底座；具体索引/媒体/权限消费者与最终进程部署尚属后续任务。

## 原子与权限边界

- 同一租户事务内完成业务写入、C01 Outbox 与 `knowledge_jobs.add_job`。任一步失败全量回滚；队列 payload 仅含 workspace/outbox UUID，不复制正文。
- dispatcher 锁定精准租户事件，按服务端固定映射 fan-out，调度消费者与 dispatched 标记同事务提交；未知 topic/非法引用/跨租户引用明确失败保留重试。
- 事件 ID/JSONB 语义相同永久去重，冲突内容拒绝。Graphile 成功后会删除 job，但 outbox 保留，故完成后重复事件不会重新执行。
- 使用普通 non-owner/NOBYPASSRLS 角色。管理员只初始化第三方 `knowledge_jobs` 与最小 grants；RLS 仅对指定运行角色开放队列基础设施，不改变业务租户隔离。运行时无法 DDL、TRUNCATE 或修改 migration 记录。

## 真实故障验证

`bun test backend/src/knowledge/workers/workers.integration.test.ts`：**11 passed / 0 failed，56 assertions**。

覆盖业务写/Outbox/调度一起回滚、调度权限失败、8 个并发相同事件、完成后永久去重、冲突拒绝、两个消费者 fan-out、真实指数退避重试（非假计时器）、外部效果已提交后失败重试的领域幂等、错误脱敏、未注册路线、跨租户/多余身份字段、fan-out 第二条入队故障回滚、最大尝试耗尽后显式恢复。

真实子进程取得任务锁后由测试父进程定向 SIGKILL；等待进程确已退出，验证队列仍有锁定任务，再用官方 `forceUnlockWorkers` 解开已确认停止的锁拥有者。重启普通角色 runner 后完成同一 idempotencyKey，任务未丢失。只清理本轮 helper 创建的随机 disposable 数据库，已确认删除，不修改主知识库数据。

正常停机测试等待 handler AbortSignal、两次并发 close；返回时无残留锁，pool listener 数量回到原值。测试发现 Graphile 0.18 默认非批处理完成/失败路径未等待写入，已配置 zero-delay 可排空 batchers 修复；停止状态 health 为 degraded，不伪报 ready。

`pnpm backend:typecheck`、针对 workers 的 `eslint --no-ignore`、依赖方向检查通过。

## 范围说明

- 投递至少一次，非 exactly-once。非幂等第三方动作必须自己使用 idempotency key 或可恢复状态机；Outbox 不提前 GC。
- 25 次重试耗尽仍保留；显式重试操作不得盲目清空队列。
- 上游原生锁失效窗口为四小时（已查 pinned 实现），本次没有等待四小时或宣称立即自动故障转移；快速解锁仅在确认旧进程已停止后进行，不能抢解活跃任务。
- PostgreSQL 队列机制真实验收；最终 API/WS、具体消费者、用户任务状态 UI 与部署监督并未借此勾选。
