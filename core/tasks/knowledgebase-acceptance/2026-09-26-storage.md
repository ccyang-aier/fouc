# D02 · 租户事务与 RLS

日期：2026-09-26。

- `bun test backend/src/database/knowledge/tenant.test.ts backend/src/database/knowledge/rls.test.ts backend/src/database/knowledge/tenant.integration.test.ts`：19 passed / 0 failed，483 assertions。
- `pnpm backend:typecheck`、相关文件 ESLint `--no-ignore --max-warnings=0`：通过。
- 真实 ParadeDB 空白专用数据库执行全部 `current.sql`，再安装 24 张业务表的 ENABLE/FORCE RLS；普通 `fouc_app` 无超级用户、BYPASSRLS、建库或建角色权限。
- 两租户使用相同业务 UUID，全部表 SELECT 仅见本租户；跨租户 INSERT 明确为 RLS 拒绝（42501 + row-level security），UPDATE/DELETE 无命中；缺少作用域读为空、写拒绝。普通角色临时成为表所有者时仍受 FORCE RLS 限制，测试后恢复所有者。
- 同一个 max=1 连接池在 COMMIT/ROLLBACK 后租户上下文清空；校验实际 pg_backend_pid 相同，随后另一租户正确隔离。吞掉 SQL 错误不能把数据库 ROLLBACK 误报为 COMMIT；断连/回滚失败不会把脏连接放回池。
- 临时数据库只由当次生成的 `fouc_rls_<UUID>` 名称识别并清理，删除后查询 pg_database 确认不存在；不删除或重置主开发数据库。无凭据输出。
- PostgreSQL 最佳实践用于 FORCE RLS、最小权限角色、索引化 workspace_id 以及事务级而非会话级上下文。RLS 用无作用域时返回 NULL 的单次子查询，避免逐行重复解析。

边界：RLS 提供租户存储隔离，不代替用户 membership/页面 ACL；workspaceId 必须由后续已认证服务上下文取得。独立可部署初始化入口、真实约束/Yjs 二进制往返由 D03 继续验收。
