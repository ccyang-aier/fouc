日期：2026-09-26。模块：`backend/src/knowledge/workers/`（vision.ts、vision.integration.test.ts、index.ts 接线）、`backend/src/knowledge/assets/service.ts`（asset.created 归属字段）、shared 契约（`assetDerivedSchema` 增 `model`/`generatedAt`、`asset.created` 增 `initiatedBy`——前一代理改动，已随并行任务 T02 的提交进入 HEAD，本任务未再改）。前置：AS01 asset 表 status/derived 与真实 MinIO、G01 网关 vision 档、G02 onCall 自动记账、Q01 graphile-worker 消费者模式。

## 可用视觉模型核查（如实）

`.env.knowledge.models.local` 无 `KNOWLEDGE_AI_VISION_MODEL`；唯一配置模型为 `KNOWLEDGE_AI_MODEL=glm-5.3-flash`（chat 端点 `open.bigmodel.cn/api/coding/paas/v4`）。`GET /models` 列出 glm-4.5/4.5-air/4.6/4.7/5/5-turbo/5.1/5.2/5.3/5.3-flash/5.3-flashx 共 11 个，无 4v 专用视觉模型。直接 API 探针证实 **glm-5.3-flash 原生接受 image 输入**（HTTP 200，正确描述自造 PNG「红色背景上白色对角斜线、左下角黑色矩形块」，真实 usage prompt 322 / completion 91 tokens），故 vision 档直接使用配置模型。测试读取顺序 `KNOWLEDGE_AI_VISION_MODEL ?? KNOWLEDGE_AI_MODEL`，缺任一则显式报错，不落默认模型。glm-4v-flash 经端点直连亦可达（探针 200），但既不在 `/models` 清单也不在本地配置中，未采用。

## 验收标准逐条落实

1. **真实图片经真实 MinIO 与网关 vision 档生成描述/OCR**：测试用 zlib 手写最小 PNG 编码器自造确定性图片（480×360 红底、白色对角带、左下黑色角块，约 4KB）→ 真实 MinIO presigned PUT → `confirmWorkspaceAssetUpload`（原子落 asset 行 + `asset.created` outbox + job）→ 真实 graphile-worker 队列消费 → 网关 vision 档（file part：Uint8Array + mediaType，SDK 转 `image_url` base64 data URL，经 guardedFetch 端点白名单）→ **真实 glm-5.3-flash 调用**（测试内一次调用约 4–5s）。结果 `derived = {status:'ready', description: 中文一句话描述, ocr: ''（图内无文字）, model:'glm-5.3-flash', generatedAt}`。用量级：每张图片调用 prompt_tokens≈322 / completion_tokens≈91（含少量 reasoning tokens）；测试断言 ai_usage 行 input_tokens>0、output_tokens>0，从不伪造 0。
2. **写 asset 派生且状态可查询**：derived 状态机 pending→processing→ready/failed；`claimProcessing` 仅从 pending/failed/processing 认领（崩溃残留的 processing 可被重认领恢复），`storeOutcome` 仅在 processing 态落最终态（陈旧重放不覆盖既有结果）。测试经 SQL 逐字段断言；非图片资产（text/plain）保持 `{status:'pending'}` no-op。
3. **Q01 job 运行 + 网关→G02 自动记账**：`createAssetVisionConsumer`（name `derive_asset_vision`，topic `asset.created`），测试经 `startKnowledgeWorker` 以真实队列运行（outbox→dispatch→consumer job→derived ready，Q01 任务链路全程真实）。网关 onCall→`createAiUsageRecorder`→`knowledge.ai_usage` 恰 1 行 success（tier=vision、operation=generate、provider=zhipu、model=glm-5.3-flash、真实 tokens）。幂等重放：同内容事件以新 outbox id 再派发，消费者 no-op、不重复调用模型、usage 不增、derived 不变。
4. **失败/超时/模型不可用**：结构化 `failed` + 固定安全错误码——`configuration`/`asset_object_missing`/`asset_too_large` 永久（完成任务不空转重试）；`rate_limited`/`provider_unavailable`/`timeout`/`invalid_response`/`asset_storage_unavailable` 可重试（写 failed 态后重抛 `KnowledgeJobError('consumer_failed')`，graphile 25 次指数退避，耗尽留队留痕，不阻塞其他 job——留队/恢复语义由 Q01 既有测试覆盖）。失败调用同样经 G02 落账（合成 429 注入下 2 行 error 行：tier=vision、error_code=rate_limited、tokens null）。消费中断（signal abort）由 tasks.ts 包装层在 handle 返回后兜底 `throwIfAborted`，作业仍入重试。

## 实现要点与本轮修复

- 前一代理遗留两处缺陷修复：(a) 测试模型选择硬编码 `glm-4v-flash`（不在本地配置、不在 `/models` 清单）→ 改为配置驱动 `KNOWLEDGE_AI_VISION_MODEL ?? KNOWLEDGE_AI_MODEL`；(b) `makePng` 完全确定性导致三张 320×240 测试图同 hash，asset 秒传（AS01 既有语义）返回 `reuse` 而非 upload grant，测试 3/4 失败 → 以种子像素条使每张测试图内容唯一。
- 队列负载仅 `{workspaceId, outboxId}`；图片字节在服务端从 S3 读取（HEAD 先行，>8MB 在读字节前拒绝，与网关 vision 档上限一致），负载不携存储凭证。`initiatedBy`（确认上传的成员）作为网关 `context.userId`，G02 记账归属到人。
- `AssetDerivationError` 仅暴露固定安全码；Graphile `last_error` 只见 `KnowledgeJobError` 固定码，无 SQL/负载/供应商响应/密钥。

## 明确边界

- 消费者尚未接入常驻运行时组合根（与 `rebuild_permissions`、backlinks 消费者同属待接线状态；本验收在测试内经 `startKnowledgeWorker` 注册运行）。
- 超时路径未对真实平台注入（120s 预算 + signal 中断由网关错误映射与 G01 测试覆盖；可重试语义以合成 429 验证）。
- 测试图片内无文字，`ocr` 为空串；带文字图片的逐字转录质量取决于平台模型，未在本验收评判。
- derived 的 `markdown`/`transcript`（音视频转写等）属后续媒体任务，不在 W04。
