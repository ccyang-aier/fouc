# Fouc 产品背景、愿景与定位

## 一、产品背景

Fouc 起源于一个真实、重复且代价很高的企业研发场景。

在常规开发中，研发人员通常遵循清晰的 Git 协作规范：从公司的版本仓 Fork 到个人仓，在本地完成开发并推送到个人 Fork，再向版本仓发起合并请求。这套流程在日常需求开发中运行良好。

但在客户环境或测试环境的问题定位中，代码与运行事实被割裂了：

- 配置完善的 Coding Agent、模型服务和本地代码仓都在研发电脑上；
- 报错、日志、进程、配置、部署版本和实时状态却在不断变化的远程环境中；
- 为了让 Agent 获得完整上下文，研发人员不得不在每个远程环境重复安装 Agent、配置模型服务、复制多个微服务代码仓；
- 如果现场修复验证成功，还要把修改重新搬回本地，再走 Fork、推送和合并请求流程；
- 测试问题从提单、审核、定位、修复、复核到回归，状态与证据散落在不同工具和聊天记录里。

问题的本质不是 Coding Agent 不够强，而是企业研发缺少一层能够把本地能力、远程事实、组织流程和交付证据连接起来的工作基础设施。

Fouc 首先要解决的，就是让研发人员无需把代码、Agent 和模型凭据搬到远程环境，也能在本地安全地结合远程运行事实完成问题定位与修复闭环。

## 二、产品愿景

Fouc 的终极愿景，是成为一个现代化、Agent 原生、面向个人与团队的超级工作台。

在 Fouc 中：

- 人负责设定目标、约束、优先级，处理关键判断并承担最终责任；
- Agent 负责理解上下文、提出计划、执行任务、生成制品并提交可验证结果；
- 系统负责组织工作对象、编排流程、控制权限、保留证据并推动闭环；
- Codex、Claude Code 及未来的各类专业 Agent 是可替换的执行器，而不是工作的唯一入口；
- 代码仓、问题单、文档、环境和流水线继续作为各类事实的权威来源，Fouc 只保存必要的引用、关系、快照和控制状态。

长期来看，Fouc 将从研发场景扩展到研究、分析、项目协作和日常办公，让个人或团队能够在同一套人机协作范式下完成各种复杂工作。

## 三、产品定位

### Fouc 是什么

- **统一工作入口**：用户从目标或问题出发，而不是先决定打开哪个工具；
- **Agent 控制面**：统一接入和管理不同 Coding Agent、专业 Agent、Skills、MCP 与企业连接器；
- **企业工作流引擎**：把需求、问题、开发、测试、审核、交付等规范变成可执行流程；
- **本地与远程环境桥梁**：让本地代码和 Agent 安全使用远程环境事实；
- **证据驱动的协作空间**：把任务、决策、变更、验证和审批组织成可追溯的工作记录。

### Fouc 不是什么

- 不自研基础模型，也不和模型厂商竞争模型能力；
- 不重造 Codex、Claude Code 等 Coding Agent 的代码生成与修改能力；
- 不复制所有代码、文档、日志和工单，形成新的事实孤岛；
- 不用不可控的全自动 Agent 替代企业权限、审批与质量门禁；
- 不在 V1 试图替换代码托管、项目管理、CI/CD 或可观测平台。

## 四、目标用户

V1 优先服务以下用户：

1. **企业研发人员**：维护多个微服务，需要跨本地代码与测试/客户环境快速定位问题；
2. **测试与测试经理**：希望问题单信息完整、进展透明、验证证据可复核、回归入口清晰；
3. **审核人、技术负责人和研发经理**：需要在关键节点审核方案、风险、代码与验证结果；
4. **研发效能与 AI 平台团队**：希望复用现有 Coding Agent，同时建立统一接入、权限、审计与效果度量。

## 五、核心设计原则

1. **目标优先于会话**：聊天只是交互方式，有类型、状态、负责人和结果的工作对象才是系统核心；
2. **纳管已有执行能力**：自动发现和复用用户已经安装的 Agent，不要求为使用 Fouc 重建工具链；
3. **本地能力结合远程事实**：代码、Agent 与模型凭据尽量留在可信本地，远端只暴露必要能力与数据；
4. **确定性外壳包住概率性执行**：Agent 可以推理和规划，状态、权限、审批与发布门禁由确定性规则控制；
5. **联邦事实源**：代码属于 Git，工单属于问题系统，运行状态属于环境与可观测平台；
6. **制品与证据驱动协作**：通过任务合同、补丁、报告、测试结果和决策交接；
7. **可替换的 Agent 执行端**：工作流和企业语义不绑定单一模型或单一 Coding Agent；
8. **风险决定自治度**：只读采集、本地修改、远程变更、推送和发布使用不同授权级别；
9. **先闭环一个高价值场景**：V1 先把远程问题定位做深，再复用底座扩展其他场景。
