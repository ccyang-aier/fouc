# Fouc 本机 Agent 纳管设计

本文件定义设备侧 Agent 发现、运行与授权的目标边界。外部实现研究见 [AionUi/AionCore 分析](../../../../background/aionui-architecture-analysis.md)；外部产品的功能与代码结构不是 Fouc 的交付状态。

## 定位与归属

Fouc 统一纳管用户安装的 Agent，但不替代其原生认证、更新机制或模型能力。`backend/device/` 负责本机可执行文件、会话进程、事件与设备许可；`backend/server/` 负责账户及共享资源。项目和知识库分别属于全局工作空间，Agent 安装本身是设备能力，不因为用户切换空间就复制为另一个安装。一次项目任务使用 Agent 时，必须另行绑定当前 `workspaceId`、项目/工作对象、工作目录、发起者与许可；设备令牌不能授予服务端资源权限。

```text
Provider（接入声明） → Installation（实际安装） → CapabilityManifest（探测结果）
                                               └→ Session（可恢复会话） → Run（一次执行与证据）
```

`AgentProfile` 表示用户选择的模型、模式与执行偏好，不等于另一个安装。执行器以实际安装路径和探测身份识别，不能只凭命令名或目录条目宣称可用。

## 发现与能力

发现可扫描 PATH、常见安装位置及用户指定路径；登记前验证可执行文件、实际身份、版本和启动方式。探测结果形成能力清单，记录会话创建/恢复、流式事件、工具审批、模型与模式控制等真实能力。界面按真实能力开放操作；缺能力时说明原因，不伪装统一行为。探测失败不得覆盖上一次可用配置为“已验证”。

V1 首选 ACP Driver。OpenCode 可通过原生 ACP 子命令接入；Claude Code 与 Codex 的桥接方式由 Provider 声明和运行探测决定，版本与安装路径不硬编码在产品设计中。Agent 私有扩展隔离在驱动/行为策略中，不污染共享 Session、Run 和事件契约。其他协议只有在真实需求出现时才实现，不提前建设通用插件市场。

## 会话与执行

`backend/device/src/agents/` 的 Registry、Capability、Driver 与 Supervisor 分别负责安装登记、能力事实、协议差异和生命周期；SQLite 保存安装、会话、运行及事件。统一事件应表达消息、计划、工具调用、审批、用量、完成/失败与连接状态，并携带稳定的会话/运行关联标识。进程退出或断连不能被当作任务成功。

会话状态区分运行、等待输入、等待审批、暂停、取消中、结束、失败与失联。空闲回收不能中断待审批或正在输入的任务；恢复时优先验证原生会话可用性，失败后明确告知新建会话的语义。取消要向驱动发起、等待终止并保留已有输出与诊断，不能仅停止前端流。

## 授权与安全

- 本机文件、终端与进程操作由设备运行时许可；共享项目与知识库访问仍由业务服务在当前工作空间授权。两侧条件都满足后才允许跨宿主任务。
- 高风险工具调用展示目标、参数摘要、影响范围和授权选项；一次许可不得被缓存成永久许可。团队策略和资源 ACL 优先于 Agent 自述或提示词。
- 只向 Agent 提供本次任务必需的文件、引用与环境变量；不读取或复制其原生长期凭据，不把连接器密钥传进模型上下文。
- 安装、升级、卸载和原生配置修改必须由用户显式发起。安装路径、进程退出、审批决策与结果应可审计。

## 产品界面与实现状态

Agent 设置页展示发现结果、安装来源、版本、状态、能力、连接测试及显式管理动作。项目工作面只呈现经绑定的执行器、运行状态、审批与结果；平台公开 Agent/Skill 社区目录不是某个工作空间的私有安装记录。设置与运行失败应给出可恢复路径。

当前设备包已实现 ACP 发现/探测、Registry、CapabilityManifest、会话与运行监督、审批事件、暂停/恢复及空闲回收等基础能力，代码和测试位于 `backend/device/src/agents/`。这不表示项目任务、工作空间授权、团队审批和跨设备执行闭环已经完成；它们必须结合项目模块、服务端授权和实际设备验证。验收以真实 Agent、异常退出、重启恢复、审批、取消及跨空间越权用例为准，不能只凭演示界面或协议单测。
