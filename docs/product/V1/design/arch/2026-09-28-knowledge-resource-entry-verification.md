# 知识库资源入口优化与工作空间模型确认

日期：2026-09-28。设计约束见 [主架构设计 §2.1—2.3](./fouc-project-structure-design.md#21-工作空间是用户操作与资源隔离的一级边界)。

## 实现结果

- 删除知识库入口中根据登录状态选择 GuestKnowledge 的分流和 localMode 状态。当前选择由独立资源选择 store 持有，按用户明确操作切换并保存；缺省选择已有可用的本机资源，不依据会话推断数据源。
- 两类现有资源共用 KnowledgeWorkbench 布局、PageTreeSidebar 和 KnowledgeBaseHeader，文档列表继续共用 DocumentsPage；存储、上传、编辑和服务端协作仍由各自实际能力提供。
- 原 guest 目录整理为 local，明确它是本机资源适配而非整套访客产品。登录、退出和身份错误不会替换本机资源或卸载其编辑器，内容不自动上传。
- 受保护资源在未登录时保留工作台与资源菜单，提供“登录并继续”；会话服务错误呈现重试反馈，不回退到本机知识库。恢复登录后继续进入选择的服务端资源。
- 私有查询缓存按账户身份重新建立，未认证时不读取私有资源目录；沿用服务端权威权限检查，没有放宽账户或资源授权。
- 主设计文档确立全局工作空间隔离、左侧栏切换、项目和知识库同级关系，以及应用上下文与模块状态的归属。

资源适配分支是实际存储/操作能力边界，不再是登录状态决定的整模块入口。当前仍只有既有本机与账户保护的服务端能力；本次未新增访客服务端主体或统一访客额度策略。

## 未实现边界

本次没有改动后端模型或数据格式。现有知识 workspace 仍与知识库实体混用；最左侧工作空间栏尚未接通统一工作空间服务，项目状态尚未从 shell 移出。全产品工作空间隔离与 `workspace → project / knowledgeBase` 模型需要按主文档继续实施，不能把本次页面优化描述为已完成该数据模型重构。

按会话快速模式未构建 Tauri 安装包，已验证 Web 导出与开发运行。
