# 工作空间切换与知识资源隔离验证

日期：2026-09-28。

## 问题与修复范围

原工作空间侧栏只修改 shell 的 `activeSpaceId`。知识库既不消费该状态，服务端资源也另存一个活动空间并回退到目录的第一项，本机知识库更共用一个无空间归属的存储键。因此侧栏切换没有改变知识库实际操作范围。

应用级 `WorkspaceProvider` 现在统一持有活动空间和目录，shell 仅呈现及触发选择。现有本机空间、新建本机空间和账户实际加入的服务端空间均可显式选择；登录、退出、会话错误不自动改变当前空间。

本机知识库、文档、编辑内容与资源来源偏好按 `workspaceId` 隔离。空间切换立即卸载原资源组件，重置知识库、文件夹、文档、搜索及筛选状态，取消读取并清空原查询缓存，关闭实时订阅与通知桥。服务端请求使用目录中的真实空间 ID，不做本机 ID 到服务端 ID 的猜测映射，也不自动显示其它空间。创建服务端空间的迟到结果不能替换用户随后选择的空间。

知识库菜单仅展示当前空间资源。现有创建接口真实创建工作空间及初始目录，故入口和弹窗明确命名“新建服务端工作空间”。本机资源来源不能绕过服务端工作空间成员与访问快照检查；无权限、服务异常与未登录有明确反馈。独立本机空间继续无需登录即可使用。

## 验证方法与结果

- 前端/共享契约单元与组件测试：866 项通过，0 失败。覆盖空间持久化、本机库隔离、来源偏好隔离、存储失败、身份变化以及创建结果的竞争条件。
- 浏览器使用真实页面、按钮、编辑器及网络客户端，身份和服务响应由隔离测试上下文模拟，不创建实际账户或修改服务端开发数据。
- 在 A 本机空间修改标题与正文后切换 B：B 不显示 A 内容，原编辑器退出；切回 A 后修改保留，搜索已重置。
- 刷新页面后恢复选中的空间；登录不将当前本机空间切到第一个账户空间。
- 切换两个服务端空间：文档列表分别呈现各自数据，请求携带正确 UUID，原空间事件连接关闭。
- 延迟返回 A 的文档请求，先切换至 B：返回后仍显示 B，A 不覆盖当前列表。
- 知识库菜单不出现其它空间；选择服务端空间的本机副本后撤销成员身份并刷新：显示无访问权限，既不暴露副本也不回退到 B。
- 退出后受保护的空间留在登录反馈，不发起私有请求；仍可显式切回独立本机空间，原内容保留。
- 浏览器无运行错误，原布局和样式保持不变。
- TypeScript、ESLint、架构依赖检查、知识库边界与任务 DAG 检查通过；Web 生产编译、类型检查与 6 个静态页面导出通过。

Web 开发服务常驻 `http://localhost:3000`，设备运行时 `8710` 与服务端 `8711` 复用现有进程并监听代码更新。按快速模式约定不执行 Tauri 客户端构建。

## 尚未实现的架构目标

本次修复知识库的空间切换链路，不代表所有产品模块都已完成资源隔离。服务端 `workspace` 与 `knowledgeBase` 的实体分离、平台工作空间模块抽取、统一访客主体与项目状态归属仍未完成，详见主架构文档 §2.3。旧无空间归属的本机开发数据不隐式分配到任意空间，不新增迁移或兼容分支。
