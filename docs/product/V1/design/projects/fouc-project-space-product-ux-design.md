# Fouc 项目工作台与单侧栏设计

## 产品与作用域

一个 Fouc 管理界面承载一个当前项目的完整工作台。项目是业务隔离域，以真实 `projectId` 及项目成员授权管理；不增加 workspace 实体、默认空间或嵌套项目授权层。顶部项目选择器是唯一项目切换入口，不再提供外层项目目录或项目内第二套应用导航。

项目内的任务、资产、成员管理、聊天、最近对话与个人选择状态默认属于当前项目。切换项目立即隔离内容、输入、弹窗草稿和最近记录；账户切换同时改变私有缓存范围。前端状态隔离不能代替服务端对真实项目及操作的权限校验。

社区与连接器目录是全项目可发现的基础设施；全局目录不代表共享凭据或获得连接执行权限。本机 Agent 的发现、安装与运行能力属于真实设备，Agents 页面复用该设备能力；展示同一设备的 Agent 不代表它获得任何项目资源权限。

应用始终复用同一菜单侧栏和系统栏。社区资源分类及连接器对象树属于当前工作面的资源浏览，不再建立第二套项目管理界面；进入这些服务不自动收起主导航。主侧栏默认宽度 272px，可在 204～360px 间拖动，主动收起后为 52px 图标轨道，并隐藏整个项目切换区域。主体内容独立滚动。社区、连接器固定在账户栏上方，不显示“服务”分组标题。

外壳以统一浅灰材质连接侧栏与 44px 紧凑顶栏，不显示品牌 Logo、独立品牌行或贯穿顶栏的竖向分隔线。侧栏顶行左侧为项目选择器，右侧为收纳按钮；收起后顶行只保留展开图标，导航列表与顶行之间留出 8px 间距。主工作面从顶栏下方开始，四角均为 16px 圆角，右侧贴齐应用视窗、底部留出 4px，使用单层浅描边。内部社区及连接器的树、工具栏和滚动区域仍归各页面所有，弹层挂到既有外壳宿主，避免被工作面圆角裁切。

内容上方的顶栏左侧依次是后退、前进，中央是打开的页面页签，右侧是全局搜索、通知、任务及原有窗口控制。全局搜索默认仅显示图标，点击或 Ctrl / ⌘ K 打开搜索面板，保留页面与功能搜索、无结果状态、方向键选择、回车导航、Escape 关闭及回焦；不在顶栏保留常驻输入框。主页面切换写入浏览器历史，无可用记录时禁用对应箭头，重复进入当前页面不叠加记录，后退后进入另一页会舍弃前进分支。设置的打开、分区选择和关闭属于当前页面的覆盖层，不新增页签或主页面记录。导航历史仅作用于当前身份、来源与项目会话，切换范围重新开始，不借助历史恢复已离开的项目或扩大资源访问权限。

侧栏菜单、搜索及页面内导航共用页签入口：第一次打开创建页签，再次进入切换到已有页签；当前存在同一页面的多个副本时，优先保留当前匹配页，再选择已有页面。页签显示与侧栏相同的图标、名称和独立关闭按钮；页签沿用 Fob 的 32px 高、128px 宽与 8px 圆角，非当前页透明，当前页采用面板色背景、柔和单层描边和适中加粗标题，置顶增加 16px；单页签在窄容器内继续收缩。选择面以弹簧位移衔接，新建和关闭采用轻微缩放与淡入淡出，页面切换以约 180ms 轻淡入衔接。超出宽度时横向滚动并显示左右浏览按钮，指针位于页签区时纵向鼠标滚轮转为水平浏览，保留原生横向触控板手势及 Ctrl 滚轮缩放；手动浏览不改变当前页或自动拉回。打开、切换及重新选择当前菜单页时，当前页及关闭按钮自动进入可见范围；键盘左右箭头、Home／End 切换，Delete 关闭当前页签。关闭非当前页不切换；关闭当前页选择左邻，首项选择右邻，关闭最后一个页签打开新的空白对话页。关闭动作只释放页面，不删除其业务资源或对话历史。

纵向滚轮按时间阻尼平滑追随累计目标，松手后短暂滑行，反向输入从当前位置立即转向，边界内收敛且不回弹；原生横向手势继续由浏览器处理。手动浏览会取消待执行或进行中的自动定位，尺寸变化、后台置顶／关闭／重新加载及菜单回焦均不拉回激活页。明确的打开、切换、重选和新建操作发出独立定位请求，停止惯性后定位目标页；请求只属于当前界面会话，不进入页面恢复数据。

新增及关闭一次确定页签布局宽度，退出项脱离布局并裁切在最终内容范围内；只对同一组页签的排序变化执行位置插值，避免浏览器收缩滚动范围与布局动画互相补偿造成末尾反向位移。自动定位统一合并到溢出按钮布局稳定后，按最终布局坐标计算最小滚动，不读取动画中的矩形或在动画结束时重复校正。

页签可沿水平方向拖拽排序：超过轻微移动阈值才开始拖动，拖动项跟随指针，相邻页签以弹簧位移让位，释放后吸附回新位置，靠近滚动边缘时继续浏览。拖动只调整顺序，不重建页面或改写其位置参数。置顶页签排在左侧并显示图钉，允许在置顶组内调整顺序，普通页签不能拖到置顶组前；置顶、取消置顶不切换当前页面，置顶状态参与本机恢复。

页签右键或键盘菜单键／Shift F10 打开统一操作菜单，提供置顶／取消置顶、重新加载、复制标签页、关闭、关闭其它标签页和关闭全部标签页；操作对象是打开菜单的页签。重新加载只重建目标页面并恢复可保存草稿、筛选和滚动位置，不刷新应用或影响其他页面。复制在原页后方新建独立页面实例，置顶页的副本进入普通页签区；复制其位置参数及可恢复界面状态，后续草稿与筛选独立。同一资源的业务内容仍由原功能所有者共享，对话副本读取同一消息历史，避免互相覆盖。批量关闭包含置顶页签，无其他页时禁用关闭其它操作；保留页面的实例与状态不变，当前页被移除时选择最近的保留左邻，没有左邻则选择首个保留页；关闭全部创建新的空白对话页。

最后一个页签右侧始终提供新建图标，页签较少时紧跟末项，溢出时保留在滚动区域右侧可见位置。单击创建独立空白新对话页，不复用已有草稿；右键或键盘菜单键打开页面创建菜单，当前仅提供新对话，通过统一页面选项列表预留后续扩展。副本拥有独立页签标识，参与排序、恢复和浏览器历史，不能因页面名称或目标相同被去重吞并。

打开的页面在当前应用会话中保留实际页面实例、输入草稿、筛选、列表样式、滚动位置以及页面运行状态；首次进入才创建，切换时隐藏并隔离键盘交互，关闭页签或切换身份／项目才释放。后台页暂停面向整页的快捷键，不抢前台焦点；原生模态表单在浏览器历史离开页面时关闭，避免隐藏模态继续阻塞窗口。页签顺序、激活页和可恢复页面状态保存到当前设备的 IndexedDB，按账户身份、项目来源与项目 ID 隔离；刷新、重新打开和切回项目时恢复，项目及账户切换只释放运行中的页面，不删除其恢复记录。恢复等待身份确认、项目选择及本机记录加载完成，避免访客记录提前改写账户的启动地址。首次显式页面／工作台链接优先于上次激活页，启动意图只消费一次；普通启动入口恢复上次激活页，后续身份切换恢复各自记录。失效的对话页签被移除，资源页继续经过原有权限与存在性检查。

页面状态由各功能声明保存：对话草稿、附件、模式与上下文，社区与连接器的筛选／排序／视图及详情选择。File、Blob 和 Date 使用结构化克隆保存，避免丢失文件内容或日期类型。工作台、对话、社区、连接器的主滚动区使用稳定标识恢复，等待异步内容具备足够高度，新交互会取消尚未完成的自动恢复，避免跳动。临时模态及未接入的嵌入式视图不承诺跨进程恢复；保存失败通过 AppAlert 提示，当前会话仍可操作。关闭页签仅清理其页面恢复状态，不删除预览对话或业务资源。

非激活页签保持浅灰容器背景，深浅主题都保留与当前页的视觉层级。页签操作菜单采用共享菜单材质、统一图标、圆角及紧凑间距，不添加头部、目标名称或数量；前三项页面操作与后三项关闭操作使用内缩分隔线分组。

首页对话按真实预览 ID 打开独立页签，侧栏重复打开同一对话切换到已有页面，主动复制可以保留多个视图。新对话首次发送后将当前草稿页转为该对话，保留输入组件实例，名称随对话重命名更新；之后点击侧栏新对话打开或切换空白草稿页。删除对话同时关闭其所有副本页签，删除当前对话回到空白对话页。项目频道是独立服务端聊天资源，侧栏点击频道定位到聊天页面内对应频道，不与首页对话预览混用 ID 或存储。

主导航与业务控件从统一图标语义目录选择，默认使用 Font Awesome 7 Solid，只有明确的轻量轮廓控制使用集中维护的 Lucide 例外，具体规范见[图标系统](../../../../ui/icon-system.md)。选中时保持图形和灰度，由共享行背景、描边和文字反馈表达当前项。菜单行激活保持浅灰 `#efefef` 平面底条，hover 使用 `#fafafa`，均保留轻描边，不使用白底浮起阴影。普通鼠标焦点不维持高亮；只有当前页面使用激活底色，键盘焦点与行内菜单展开复用较轻的交互反馈。保持 Fouc 现有浅深主题与字体，主导航不引入额外彩色背景或另一套样式体系。

新对话保留原有气泡图标，与工作台等主菜单项使用相同行高与行距。智能体入口随界面语言显示“智能体”或“Agents”，其下方使用两侧留白的分隔线。置顶、频道、最近采用带折叠箭头的分区行，标题 12px，内容向内缩进，频道、最近标题右侧保留更多和新建入口，置顶标题只提供折叠。标题整行只在 hover 时显示浅灰背景，鼠标离开立即清除，不因展开状态、菜单打开或鼠标点击后的焦点保留底条；键盘定位只显示边框。条目背景左右边界与主菜单对齐，12px 层级缩进放在条目内部，保留图标和文字的视觉缩进。

底部身份与操作使用一行布局：左侧是浅灰底的头像与用户名入口，hover 时加深至 `#e4e4e4`，保留设备状态角标与账户菜单；右侧依次是主题和设置图标。主题按钮采用基于 Magic UI 的共享 `AnimatedThemeToggler`，点击后以按钮中心为起点，在 400ms 内圆形扩散至整页，直接切换浅色与深色；复用已有外观偏好并持久化，与设置页同步。跟随系统仍在设置页选择，按钮图标随系统实际明暗状态更新。设置图标打开现有设置弹窗。收起后底栏仅保留居中的账户头像及提示，隐藏主题与设置。

频道分区承载多人聊天入口，不另设“聊天”主导航。条目、顶部频道下拉与标题共用服务端保存的频道图标和配色；未配置图标时使用 `#`，创建时未指定配色则在五种内置彩色中随机选择并保存，刷新不重新随机。新建和设置提供十六种内置图标及六色选择，灰色可手动选择，不开放任意取色。点击条目进入对应频道，并以当前可见频道同步选中反馈；新建进入频道表单，创建者可从行内菜单设置或确认删除，侧栏收起时仍保留频道入口。名称排序属于当前视图。侧栏置顶与页面收藏共享本机偏好，按完整身份、项目来源与 ID 隔离，不重复渲染已收藏频道。频道上方按需显示统一置顶分区，聚合收藏频道和置顶首页对话；没有内容时隐藏分区。对话按更新时间排列，最近仅取未置顶对话的前六条，置顶对话不占名额。条目操作仅在 hover、键盘焦点或菜单打开时显示，顺序为置顶／取消置顶、更多；反馈复用共享 AppAlert 和危险色。切换项目关闭未完成弹窗，导航意图只消费一次，确认目标不因后台目录刷新转移到另一频道。

## 顶部项目切换

侧栏顶行的大半部分为紧凑项目入口：左侧 24px 圆角流体染料图标、可截断项目名、右侧双向切换标识。图标维护有连续历史状态的二维速度场与四路颜料浓度，通过压力投影与平流使不同大小的色团缓慢推挤、卷入和交融；误差校正与局部扩散共同保持自然的混色边界，柔和密度明暗表现颜料厚度。流速按实际 24px 尺寸校准，持续观察几秒即可看见色团位移与卷曲；采用小步推进保持连续自然的液态感。容器始终填满，新流场使用随机初始分布，刷新页面不重播固定开场；项目入口与列表共用项目流场，切换配色保持流动连续，六个配色预览各自维护独立流场与相位。菜单关闭或离开视口时停止推进与绘制，重新显示从保留状态继续；会话内最多保留 24 个未使用流场，超出后按最久未使用顺序释放，不保留 Canvas 或动画调度。项目 ID 只决定稳定默认搭配，切换菜单中的“图标配色”提供六组可切换染料，偏好按身份、来源与项目保存在当前设备，不改变项目权限或主题。项目入口沿用外壳底色，轻量悬停反馈与图标建立当前项目身份；收起时隐藏整个项目切换区域，展开后恢复入口。

弹窗顶层搜索真实可访问项目，列表显示项目名称、真实本机／团队来源及当前选择勾号。搜索无结果、加载和服务失败分别反馈；底部提供新建、当前项目重命名及删除。没有项目时展示选择／创建引导，不伪造默认项目，不回到已删除的外层项目目录。

创建与重命名使用紧凑独立表单，空白名称禁止提交，提交中显示共享三点反馈，失败保留输入；团队项目调用真实服务端用例，本机项目由浏览器明确保存。删除保留危险色及确认，只有真实成功后更新目录和当前选择；服务端继续校验项目管理权限。切换后进入目标项目工作台，失效选择只能回落到真实可访问项目。

## 页面边界

| 页面 | 本次内容 |
| --- | --- |
| 工作台 | 迁移现有项目 Dashboard 首页及其必要交互 |
| 任务 | 项目隔离的多任务看板、Kanban、日历排期、细粒度任务与看板成员授权 |
| 成员 | 团队页的成员目录、卡片／列表、自由标签与详情；团队结构显示暂未开发 |
| 资产 | 保留独立入口及清晰空状态，暂不迁移原分区 |
| 智能体 / Agents | 真实本机 Agent 发现、登记、状态与管理能力，不在侧栏展开二级列表 |
| 服务 | 社区和连接器全局目录 |
| 频道 | 服务端项目多人聊天频道、用户与自有 Agent、话题、投票、附件与频道资产；通过侧栏频道分区进入，尚无记录时显示空状态 |
| 最近 | 当前项目最近对话的投影，点击恢复该对话 |

旧项目目录、旧项目管理侧栏，以及旧工作台的 My Task、Inbox、Reporting、Portfolio、Accounts、Goals 等独立分区与专属依赖清除。自动化菜单、页面、演示数据和唯一依赖从产品移除，不以隐藏路由或兼容入口保留。

## 工作台首页

首页延续用户指定视频 `opensource/dribbble/produtc-design-01.mp4` 的内容布局，去掉视频页面自身的身份侧栏、导航、顶部工具栏及重复字体系统。快捷创建、统计、活动时间线、团队、今日项目卡、会议、里程碑与动态在统一 Fouc 工作面内呈现。通用图标复用 Fouc 的统一 FA7 Solid / 既定轮廓例外，主题与字体继承系统。

统计与“查看全部”入口导航至主菜单对应页面，不重新展开旧分区。创建账单、提案、合同、表单，以及首页卡片详情、任务、会议、协作者和里程碑的必要弹窗保留；取消不保存、提交保留真实反馈、关闭恢复焦点。

工作台参考人物、项目卡、任务、统计与活动仍是本机界面交互样例。它们按身份、项目来源和真实项目 ID 独立保存，不写入服务端项目业务表，不形成真实团队成员资格，与任务菜单的真实看板数据独立；资产页面仍未接入业务持久化。“今日项目”中的样例卡是首页组合内容，不是额外项目隔离域。

活动时间线按样例任务排期和会议生成，支持日／周／月／年窗口及详情；里程碑支持目标和历史编辑、范围切换与导出。首页统计来自当前作用域记录，不使用隐藏固定基数。文档就绪、完成或会议导出只表示本机记录状态，不表示发送发票、签署合同或发布外部表单。

任务、文档、会议链接携带完整作用域，只能在相同身份、来源、项目以及该设备已有记录中恢复；不同作用域的同名样例不互相打开。用户编辑的正文、姓名、文件名和协议标识不随语言切换被覆盖。参考附件缺少真实文件时仅展示来源说明，不伪造下载内容。

## 项目成员

团队页面使用单个“团队”标题和“成员／团队结构”页签。成员页仅保留一个新增成员入口；下一行显示成员数、搜索、标签筛选与统一 ViewSwitcher。团队结构只显示“暂未开发”空态，不展示旧部门看板、成员工具或新建部门操作。

成员卡片按“48px 独立生成头像、姓名与职位”“部门与邮箱”“自由标签”分组，采用共享资源卡片的单层描边，不叠加外层卡框、阴影或悬浮位移。卡片保持固定可读字号，随容器宽度调整列数；标签允许换行，卡片自然增高。列表保留姓名、部门、邮箱、标签和加入时间，窄窗口横向滚动。电话与完整资料在详情中编辑。

标签是成员的自由文本标记，以 `{name,pinned}` 数组保存，例如“小组二组”“请假”，不承载在职状态、项目角色或授权含义。详情支持搜索复用已有标签、新增、移除、置顶与取消置顶，名称去首尾空白、最长 40 字、同一成员内忽略大小写去重。置顶标签优先展示；修改随成员详情一起保存，取消不改变目录。目录搜索包含标签名称，标签筛选提供搜索，删除最后一个匹配标签后清除失效筛选。

当前成员主页面使用参考资料进行本机交互预览，目录编辑、自由标签、搜索、当前页签与卡片／列表选择通过既有身份、项目和页面隔离的恢复状态保存在本机，刷新可恢复；这些预览资料不代表真实项目成员关系，也不写入业务服务成员授权。已实现的 `/api/projects/:projectId/members` 账户成员与角色管理接口继续由 modules/projects 拥有，公开契约经 @fouc/shared/projects 导出，服务端按真实项目、会话与管理权限校验。成员标签未接入该接口，不改变项目或看板的访问权。

## 项目任务看板

任务菜单面向真实服务端项目中的团队需求与任务跟踪。一个项目可创建多个独立看板，用于个人待办、项目交付或某项特性；不存在全局任务空间。顶部用可搜索的看板切换器收纳目录，保留新建入口；选择、搜索、筛选、排序和滚动位置进入已有按身份与项目隔离的页面恢复记录。任务正文始终从业务服务读取，界面恢复记录不代替资源授权。

任务页复用系统栏的历史前进与回退，不重复展示菜单面包屑。页头使用 16px 的紧凑看板名称，附可见性；右侧显示真实更新时间、最多三个 28px 成员头像与圆形剩余人数，创建人另有 30px 高的黑色“邀请”按钮。页头与卡片共用全局 `AvatarGroup`，真实头像、姓名 Tooltip 及 `+N` 溢出展示保持一致；页头头像组直接呈现，不附整组胶囊容器、描边或 hover 背景，键盘焦点通过头像自身的边界反馈。头像组和邀请入口打开其下方的非模态成员浮层，保留原有成员授权、邀请范围与错误反馈，支持点击外部或 Escape 关闭及嵌套权限菜单，不遮挡或锁定整页。浮层直接展示可按姓名／邮箱过滤的成员列表，不添加重复标题、范围说明或关闭图标；添加受邀成员使用独立搜索。权限菜单宽 128px，使用查看／编辑图标，以加粗表示当前项，不叠加勾选。头像组保留成员管理的可访问名称。描述在看板设置中维护，不占据独立说明行。

下一行工具栏移除完成率摘要。左侧展示用户创建并命名的视图，默认 0 个；圆形加号在下方打开非模态的紧凑创建浮窗，支持看板、日历、表格三种类型及同类型多个实例。每个视图可重命名和删除，删除只移除视图配置，保留任务与状态列。零视图时展示创建入口，只读成员显示空状态。配置由服务端按看板持久化，所有有权访问看板的成员共享；创建、改名和删除遵循看板编辑权限，每个看板最多 24 个视图。当前视图及各视图独立的搜索、筛选、排序、日历范围、表格折叠与滚动位置进入按身份、项目、看板、视图隔离的页面恢复记录。

视图导航无外框，图标位于自定义名称之前；按钮 30px 高、文字 12px、图标 18px。看板使用四格图标，日历使用日历图标，选中项使用共享中性底色和加粗文字；视图名称通过右键或 Shift+F10 打开操作菜单，提供重命名和删除，不显示独立省略号按钮；重命名使用锚定该视图的轻量输入浮窗。圆形新建入口点击区 30px、图标 20px，不显示文字、黑底或下拉箭头。工具栏不绘制下分隔线。存在视图时，右侧依次排列负责人、筛选、双向排序箭头、闪电、搜索、更多；图标按钮采用 `--control-border` 单层细描边，30px 方形、间距 6px、线性轮廓图标 16px。负责人菜单只展示真实成员，当前用户在第一行，不重复显示全部负责人、分配给我或未分配三个特殊选项；可按姓名／邮箱搜索，再次选择当前成员或清除筛选恢复全部任务。两组控件保持同一高度与垂直中心线。右侧工具按钮常态使用全局“浅灰白色” `--interaction-hover-bg`（浅色 #fafafa），与系统侧栏菜单项 hover 完全一致；hover／按下／展开／有效筛选使用“灰白色” `--interaction-active-bg`（浅色 #efefef）；左侧视图与圆形新建入口仍保持透明常态，深色模式使用对应灰度。所有下拉不添加冗余标题或说明，负责人、标签、状态列和看板等可增长列表提供搜索，固定少量操作不添加搜索框。菜单入口、单选项与子菜单从统一 FA7 Solid / Lucide 语义目录选择图标，请求尺寸 16px、实际图形 14px；优先级菜单与卡片复用同一旗标组件，日期、标签及排序选项也显示对应图标。带图标或头像的选项不再叠加对勾及其左侧占位，选中项保留加粗与 ARIA 状态。闪电菜单复用分配给我、逾期和清除筛选，更多菜单提供新建任务和新增状态列。系统导航与主页面菜单统一遵循 [图标系统](../../../../ui/icon-system.md) 的语义选型，不逐处更改图标权重。任务搜索在按钮下方弹出输入浮窗，不挤压工具栏，关闭浮窗保留当前搜索条件；搜索条件清除后恢复全部任务。负责人筛选菜单宽 184px，标签筛选菜单宽 164px；“全部”选项不加粗，具体选项保留原选中反馈。工具栏底部留白 6px、画布顶部留白 8px，缩短工具栏与状态列之间的距离；窄窗口按操作组换行。浅色模式的任务画布与页头统一使用白色面板背景，列容器用浅灰背景分组，卡片保持白色。

新看板默认仅创建人可见。可见性与编辑权限独立：

| 可见性 | 可见成员 | 编辑及管理 |
| --- | --- | --- |
| 仅自己 | 当前项目中的创建人 | 创建人编辑并管理 |
| 项目可见 | 当前项目的全部成员 | 默认只读，创建人逐人授予编辑 |
| 受邀成员 | 创建人与明确加入看板的项目成员 | 新成员默认只读，可由创建人授予编辑 |

只有创建人管理看板名称、描述、可见性、成员和删除；项目 owner／admin 不绕过其他人的私有看板权限。编辑者可管理任务、状态列与评论，只读成员只能查看。受邀成员从真实项目成员中选择，不通过此功能创建账户或扩大项目成员资格。撤销项目成员资格立即失去看板访问；重新加入项目不恢复先前邀请。切换为私有时清除成员授权及失效任务分配。任务负责人仅可从当前具有看板访问权的项目成员中选择，返回数据过滤失效负责人。前端响应权限变化并重新查询目录。

本期完整实现 Kanban、任务日历与分组表格。默认列为待处理、进行中、待审核、已完成；编辑者可新增、重命名、调整语义色、设置完成标记、左右重排和删除空列。列头使用状态环、计数徽标、列操作点阵菜单和添加入口；已完成沿用半实心圆形并固定绿色，不添加勾选。列操作使用横向六点图标，短按打开菜单，长按 400ms 后拾起整列进行水平拖排；提前移动超过 6px 取消长按，Escape、指针取消或窗口失焦撤销拖动。左右菜单移动与拖动换位共用平滑位置动画，整列内容随列移动；释放后一次保存完整列顺序，失败回到原顺序。删除项不附说明小字，非空列与最后一列仍禁用删除。完成标记决定真实完成数，不依赖列名；非空列必须先移走任务。

卡片头展示稳定任务编号、实际进度圆形指示与更多操作。进度来自检查清单，完成列内任务按 100% 呈现；无清单的未完成任务显示空环。常态蓝色，距截止日不超过两个本地日历日（含逾期）且进度低于 70% 时显示警示红色，完成任务不预警。指示支持 hover／键盘焦点 Tooltip，说明百分比、已完成清单数／总数及到期预警。正文常态使用无边框白色卡面，hover、按下、键盘定位及卡片菜单展开时显示浅色单层虚线边框，边框不改变卡片尺寸，交互时卡面背景保持不变；保留紧凑标签和优先级，移除独立清单进度区域；普通优先级旗标为蓝色填充，低为中性轮廓，高为橙黄色填充，紧急为红色填充。底部采用两行结构：首行为负责人文案及最多三个 24px 头像和 `+N` 圆形溢出，次行左侧使用带网格点的日历图标与日／月／年日期，右侧固定呈现回形针附件数与对话框评论数，这一行图标统一为 16px。两个计数为零时同样显示；评论数来自服务端，当前任务尚不接收附件，附件数为 0，不伪造非零统计。

任务包含看板内从 1 递增的只读编号（展示为 `TASK-1`）、标题、纯文本描述、优先级、多负责人、截止日期、标签、可勾选检查清单，以及独立的排期（起止时刻与可选关联链接）。编号在看板写事务中分配并持久化，编辑、移动和排序不改变编号，删除不回收编号；数据库以项目、看板和编号共同约束唯一性。分配函数验证当前会话与看板编辑权限，只更新内部计数，不授予编辑者修改看板设置的权限。点击卡片打开右侧悬浮详情卡片，四周留出间距，使用圆角、轻描边与浮层阴影，默认 400×760px，可从顶部空白区域和任务编号拖动位置，任务编号也支持方向键微调、Shift 加速；拖动限制在可见区域内，Escape 取消当前拖动并恢复原位置，标题输入和关闭操作不触发拖动。尺寸固定，不提供缩放手柄；小视口内按可用空间收窄和限高，窗口变化后保持卡片可见，内容区独立滚动，底栏始终可达。移除独立页头，任务编号位于 18px 无框标题左上，右上保留关闭入口。所有宽度均使用“任务信息”“子任务”“评论”三个并列分页签，子任务位于任务信息右侧并显示数量，不因宽度充足改为双栏。任务信息编排浅色属性容器、排期和描述，属性、排期与描述统一采用左侧标签、右侧值的两列布局，值区域填满卡片剩余宽度，描述输入框位于右侧并与属性和排期输入框对齐；子任务在独立分页签中使用完整正文宽度，直接展示列表与已完成统计，不再使用折叠容器或进度条，勾选框使用中性色。每项拥有独立的可空单人负责人 `assigneeId`，与任务的多负责人字段互相独立；负责人从当前看板成员（含创建人、编辑者和只读成员）中搜索选择，可恢复为未分配，标题、完成标记和负责人随任务草稿一起保存，切换分页签保留草稿。服务端重新校验项目成员与看板可见范围，拒绝分配给无看板权限的用户，只读成员不能修改；移除受邀成员或收紧看板可见性时清理失效分配，读取时也过滤不再有权限的负责人；“添加子任务”为可点击按钮，新增空白子任务后立即聚焦标题，保存前须填写标题或移除空项；评论使用独立分页签，直接沿用详情卡片底色，不叠加背景或内层圆角容器，不绘制区域分割线。评论内容保持挂载，面板或尺寸切换保留草稿，底栏始终可达。可保存、取消、确认放弃或删除；评论独立提交，显示真实作者与时间，作者或看板创建人可删除自己的授权范围内评论。只读时隐藏变更入口。任务页状态与优先级复用共享 Radix 菜单封装的 TaskSelect，动态状态支持搜索，负责人使用与触发框等宽的可搜索多选菜单，单行头像与姓名，触发器与状态控件同宽；日期和时间复用同一 DatePicker 控件，所有入口使用紧凑日历与时间双栏、统一图标和焦点反馈，确认后更新、取消保留原值；日期字段输出日期，排期字段保留日期时间精度。评论无内容时复用通用空状态组件，以空数据图和“暂无评论数据”呈现，不增加辅助说明。原生顶层弹窗包含键盘焦点、Escape、草稿保护、失败恢复及危险操作确认；共享下拉菜单在打开时解析当前弹层宿主，子菜单继承该宿主，避免关闭浮层后仍挂载到失效节点。按钮使用共享三点 loading，消息复用 AppAlert。

任务详情保存以打开详情或上次成功保存时的草稿为基线，只 PATCH 本次实际修改的字段；后台刷新不替换该基线，避免只改描述时覆盖其他成员刚完成的拖拽、负责人或检查清单变更。没有字段变化时不提交写请求；保存失败保留草稿，评论草稿使详情保持打开时，成功保存同步更新基线。

标签属于各任务，以 `{name,color}` 数组直接持久化；名称去空白后 1–40 字，任务最多 20 个，同名去重保留首项颜色。内置蓝、紫、玫瑰、橙、琥珀、绿、青绿、青蓝八种浅彩色，深色主题对应独立色阶。详情以单行 badge 展示，hover 或键盘进入时显示删除叉，末尾加号打开可搜索复用已有标签、输入新名称并选择颜色的快捷浮窗；搜索框右侧使用无描边的小色块与箭头入口，点击在浮窗内展开八色色板，选色后收起并回焦入口，不显示颜色名称列表；备选标签按内容宽度紧凑排布、自然换行，长名称截断，超出列表高度后滚动；只修改任务草稿，保存任务后生效。卡片、表格和标签筛选复用同一 badge。标签不新增全局或看板资源实体，筛选按名称匹配，新建同名标签优先复用当前看板已有颜色。

支持同列重排、跨列拖动以及任务菜单移动，移动与排序落库。拖拽预览复用原卡内容，以端正卡面和浮起阴影呈现，原位置卡片淡出；目标落点显示与源卡等高的圆角虚线占位，不再使用细插入线。浏览器原生拖拽图像保留鼠标在卡片上的抓取位置，取消或落下后清理预览与占位；仅参考拖拽外观，不改变卡片内容结构。筛选与自动排序时停止手动拖排并提示恢复方法，避免隐藏任务造成不明确的位置。搜索匹配编号、标题、描述和标签；筛选覆盖负责人、优先级、标签、逾期和未来七天，排序覆盖手动、优先级、截止日期、更新时间和名称。逾期判定使用本地日历日并排除完成状态。可见页面每十五秒及重新聚焦时同步，隐藏页停止轮询；这不是多人实时协同编辑协议。

表格以真实状态列分组，使用轻描边圆角分区、浅灰表头和紧凑单行任务；按任务、描述、负责人、开始日期、优先级、状态、标签与操作排列，负责人复用 AvatarGroup，状态徽标沿用列语义色，长文案及标签截断但可读取完整内容。开始日期仅来自独立排期，不用截止日或创建日替代；未排期明确展示。分组可折叠并恢复，空组提供创建入口，点击任务打开已有详情，行菜单复用 Kanban 的编辑、移动和危险删除确认。可在状态单元格直接移动任务；行和组选择提供半选反馈，批量移动只包含当前筛选可见且仍有访问权的任务，逐项经原任务 API 授权和保存，失败保留选择并刷新已完成部分。只读成员保留详情和分组浏览，隐藏所有选择及变更入口。三种视图类型复用同一套搜索、筛选和排序逻辑，各实例独立保存条件；窄窗口保留完整列并横向滚动，不压缩字段至不可读。

评论输入区初始文本高度为 38px，随内容增长至 140px；底部提供图片和表情入口，保持紧凑操作条。图片可通过文件选择或粘贴添加，每条最多 4 张、每张不超过 5 MB，接受 PNG、JPEG、GIF 和 WebP；发布前显示可移除的本机预览，发布时才上传，也可只发布图片。表情使用可搜索、支持键盘选择的轻量浮窗，选择后插入当前光标位置并回到输入框。发布失败保留文字和图片草稿，切换任务信息／评论面板不丢失草稿；发布后的图片显示缩略图，可打开查看原图。

业务用例归 `backend/server/modules/tasks`，前端归 `features/tasks`，公共类型和输入约束经 `@fouc/shared/tasks` 导出。`resources` 下的看板、看板成员、状态列、任务、评论五张表使用组合外键与强制 RLS；每次读写同时验证有效身份、当前项目成员资格和看板权限。评论行以 `images` JSONB 保存图片标识、名称、类型和大小，文件由任务领域写入 S3；上传校验实际文件签名，读取逐次验证项目、看板、任务和评论范围，不向前端暴露存储凭据或公共对象地址。失败事务清理已上传文件，删除评论、任务或看板后清理对应图片；对象清理失败不撤销已成功的业务删除。评论发布接口仅在对应 POST 路径接受有界 multipart，其余资源写接口保持 JSON 与原请求体上限。视图以看板行的 `views` JSONB 数组保存 id、名称和类型，默认空数组；服务端在已有看板锁内完成创建、改名与删除，受控数据库函数仅允许有编辑权的有效会话修改视图数组，不扩大看板设置的 owner 权限。写操作在看板锁内串行并重新确认权限，排序与内容变更作为同一事务完成。当前唯一 schema 直接维护在 `current.sql`，不引入旧开发数据迁移或兼容路径。

日历沿用当前看板、真实任务与成员权限，参考日程网格的浅色状态卡片、紧凑状态徽标、负责人头像和锚定创建／编辑浮层。工具栏提供日／周／月切换、前后翻页、今天与日期跳转；时间范围和锚点日期进入已有按身份、项目、看板、视图隔离的页面恢复记录。周从周一开始，日／周按本地时区绘制 24 小时时间轴，标记当前日期与时间；重叠排期并列分配位置，跨天排期在每日边界分段。月视图显示真实日程及未排期任务的截止日，点击日期进入单日，额外任务通过计数入口进入当日查看。没有预留时段的任务保留在可搜索的未排期列表；仅有截止日期的任务显示于日／周顶部的截止日区域，不为其虚构起止时间。

排期属于原有任务，不新增独立日程资源或项目隔离域。`schedule` 作为完整可空对象保存带时区的 ISO 起止时刻与可选 http／https 链接，结束必须晚于开始；取消排期仅清空该对象，不删除任务或更改截止日。编辑浮层支持标题、描述、日期时间、真实负责人、状态、优先级和链接；保留检查清单、标签、评论及截止日，快速编辑仅 PATCH 用户实际改变的排期相关字段。任务详情使用同一排期字段控件。创建和编辑执行已有看板编辑权限，查看者通过任务详情读取；日历与 Kanban 共用搜索、负责人、优先级及截止日筛选。

日／周网格可点击或以 15 分钟为单位拖选创建；任务卡片可跨日期拖动，底边可调整时长，键盘方向键支持 15 分钟移动及跨日移动。拖动期间呈现真实尺寸预览，Escape、指针取消及窗口失焦撤销；保存失败恢复原排期并使用 AppAlert 提示。创建／编辑浮层使用透明背景的原生顶层弹窗，位置随锚点与可用区域约束，包含原生焦点管理、Escape、未保存内容保护、真实成员搜索和共享菜单；字段校验保留输入，保存失败保留草稿，按钮使用共享三点 loading。窄容器先换行操作组，再保留时间网格的横向滚动，状态卡片和控件随系统深浅色主题保持可读。

本机项目不伪造服务端看板；该入口提示从顶部切换至服务端项目，访客可进入既有登录流程。登录、退出不迁移任务内容。首页交互样例继续独立于真实看板；本期不增加附件上传、AI 自动拆解、外部通知、项目邀请或执行调度。

## 聊天频道

一个聊天即一个频道，以真实 `projectId` 和 `channelId` 定位。`features/chats` 拥有频道目录、消息流和页面状态，`modules/chats` 拥有业务用例，公开契约来自 `@fouc/shared/chats`。本机项目与访客不伪造多人协作：保留清晰引导，由顶部项目切换选择可访问的服务端项目；登录不迁移首页预览或本机内容。

频道页面不增加内部侧栏，采用顶部紧凑频道下拉框、留白消息流、统一语义工具图标与轻描边附件卡，复用系统外壳和交互令牌。首行按参考图呈现“频道 / 彩色图标与频道名 / 当前页签”的轻量标题层级，频道名仍是切换入口；标题行 44px、文字 13px、频道图标 18px，下方页签行 36px。首行不展示描述和锁图标，描述及可见范围只在设置中管理。右侧只保留成员组合入口、搜索和频道操作，使用统一目录中的语义图标；邀请用户／Agent、置顶、收藏、免打扰、复制链接与管理操作按职责收在频道菜单中。新建频道只在侧栏频道区、顶部频道下拉及空状态提供。聊天区本地加载中文无衬线字体，保留既有拉丁字体；显式界面与对话字体偏好仍优先。频道下拉框宽 258px，支持搜索、未读、收藏筛选与新建；表单约 376px 宽，输入、选择及底栏按钮统一为 30px 高，内容按需展开并自然收紧高度。主区提供聊天、话题、频道资产、成员页签。正文保留舒展的阅读字号，作者、时间与正文区分字重和灰度；32px 头像、日期和输入区保持同一左侧基线，回复入口以细连接线接回作者。附件卡采用 268px 宽、约 60px 高的横向文件图标及两行信息，文件名截断不挤压上传状态；所有附件（含图片）统一使用文件信息卡片，消息内不展开图片或其他内容，点击卡片后再打开预览。消息按日期分隔，支持 Markdown、代码、附件、表情回应、置顶、编辑和确认删除。回复在右侧话题面板内进行，不冲散主消息流；搜索、置顶和频道整理按需使用同一侧面板。空、加载、失败、重试、提交中和失权均有真实反馈。

富消息按内容语义配色：投票选择与本人表情回应使用柔和蓝色，上传成功使用绿色，文档、图片、PDF、代码沿用统一的文件类型图标与识别色；导航和通用工具仍使用中性反馈。投票卡约 340px 宽、内边距 12px、选项最小高度 32px；选中、未选中、提交中、已结束状态清晰区分，结果比例融入选项背景，不在底部单独绘制进度横线。支持修改与撤回选择，提交中防止重复请求，失败保留原选择；已结束的投票保留只读结果。

频道输入、话题回复、编辑和消息正文共用真实成员名称识别；成员提及使用蓝色标签，Agent 提及使用紫色标签，支持含空格的名称和历史已离开成员，不将邮箱、未知名称标为提及，正文中的代码与链接保持原样。消息仍保存纯文本与 Markdown；编辑器采用单段落加换行的文本模型，标签和表情通过编辑器装饰呈现，不另存一套富文本正文。保留原有草稿、光标选择、撤销、中文组合输入、Enter 发送、Shift + Enter 换行、文件粘贴与附件发送限制；粘贴 HTML 只提取纯文本。

表情统一采用与 Fob 相同的 OpenMoji 17.0.0 本地原版精选集（8 类 × 56 个），输入装饰、消息、表情回应及选择器共用同一资源映射。共享选择器提供八列网格、分类、中文／英文搜索、最近使用、键盘定位与关闭回焦；未入选的用户 Unicode 保留原文字。完整资源、来源摘要和 CC BY-SA 4.0 许可规范见 [Emoji 系统](../../../../ui/emoji-system.md)。消息和回应只保存一个 Unicode 表情序列，服务端继续拒绝普通文本、多表情和不完整序列。

附件点击后使用独立阅读弹窗，最大宽度约 720px，文件名、类型、大小和操作分层呈现；Markdown 正文保留 14px 文档排版，短文档从约 300px 高度按内容展开，长文档和代码区域可滚动。图片保持真实比例，并支持适应窗口／原图尺寸切换；PDF 使用独立阅读区，其余格式提供下载入口。加载、格式不支持、访问失败与重试都有明确状态，原文件只在打开时读取；关闭、身份、项目或频道切换会回收预览资源，迟到响应不能恢复内容。

任一项目成员可创建频道，并选择项目内真实成员加入。私密频道只对成员可见；项目可发现频道允许项目成员加入，读取后仍按频道成员边界操作。创建者为 owner，可设置邀请和发言权限为所有频道成员或管理员，并调整管理员、删除频道；管理员只管理普通成员，不能提升管理员或删除频道。每次服务端操作同时验证真实会话、项目成员和频道参与者，不接受客户端提供的作者身份。被移除的成员立即失去读取和参与权限，历史作者信息保留；前端撤权后清除频道缓存、预览与未完成操作，并中止 Agent 运行，迟到响应不能恢复失权内容。

用户与 Agent 使用同一消息流、成员与话题表达。成员可将自己当前设备上启用且就绪的 Agent 加入频道，所有者来自当前服务端身份。只有用户主动提及自己的 Agent 或选择请其回复／总结才启动本机真实会话；其他成员的消息不会自动授权当前设备执行。执行使用真实 `installationId`、`sessionId` 和 `runId`，保持 `yoloMode:false`，需要操作权限时展示原始参数并由用户一次性批准或拒绝；可停止运行，失败不生成伪造回复。Agent 完成的真实文字由其所有者回写频道；执行来源是客户端提供的记录，不声称具有设备签名证明。

消息附件与资产目录共用一份 S3 私有对象和消息引用，文档、图片发送成功即出现在频道资产中。支持预览、下载、类型筛选、搜索、卡片／列表及返回原消息。单次最多八个附件，单个不超过 20 MB、总量不超过 80 MB；发送失败保留正文和附件，发送过程中锁定编辑以避免丢草稿。文本与图片可预览，其余格式保留下载。资产接口查询完整频道历史，消息快照保留最近 500 条并支持向前分页。默认频道整理仅摘录可见讨论、话题和文件；选择自己的 Agent 才进行真实模型总结，界面明确区分来源。

频道消息与成员由服务端持久化，主区可见时约 2.5 秒同步消息，频道目录和资产约八秒同步；页面隐藏时暂停主区轮询。收藏、免打扰、已读时间与草稿属于当前身份／项目的本机偏好，不宣称跨设备通知服务。分享链接仅定位本人已有访问权限的项目和频道，消费一次后不锁住顶部项目切换。

## 首页对话与最近记录

新对话始终继承顶部当前项目，输入卡不再提供“选择项目”或“不在项目中工作”。

首页预览会话按身份、项目来源及项目 ID 保存在当前设备，项目间和账户间不能互相读取。侧栏最近与首页对话页最近记录共享同一来源，重命名同步更新各处名称和当前对话标题，不修改原始消息；继续发送或编辑消息保留名称和置顶状态。删除当前对话后返回新对话，其他会话保留。切回项目、刷新或重新打开后可恢复该项目已有预览及相关页签；首页预览附件仅在本机保存，仍不下发 Agent 或模型调用。它与服务端聊天频道相互独立，不能将恢复后的首页预览呈现为真实设备执行会话。

## 授权与验证

项目选择仅定位工作台，不授予项目权限。服务端项目目录只返回本人真实成员项目，重命名和删除继续要求管理角色。切换项目时重新查询实际资源，迟到响应不能覆盖切换后的页面；具体操作始终校验当前会话与资源权限。

验收聚焦顶部项目切换、搜索、表单与错误反馈、单一导航、工作台首页保留交互、新页面空态、聊天与最近联动，以及身份／项目边界。深浅主题、键盘关闭回焦和必要窄窗口布局保持完整。开发服务常驻并刷新源码，不因本次 Web 重构构建 Tauri 客户端。

### 设计判断

Fouc 应把 ADD 变成「围绕一个工作项持续产出、验证和作出决定」的工作环境。阶段描述工作正在做什么，角色描述谁承担职责，Skill 描述如何执行，Gate 描述本次交付凭什么继续。它们在数据和界面上保持不同含义。

ADD 原文的十项活动是可穿插、复用和返工的活动池。因此不采用强制十步向导、不以完成第几步显示虚构百分比，也不把十项活动各做一列铺满横向看板。新需求从澄清进入；明确缺陷从问题处理进入复现和修复；已有架构可以引用沿用；任何活动遇到新取舍都可以插入 ADR，决定后返回原工作面。

项目仍是唯一业务隔离域。这里的「工作区」「工作室」是界面称呼，不增加 workspace 实体、默认项目或另一套项目切换。工作项组织一个目标及其关联产物、任务和交接；真实资源依旧分别授权。图中「成员邀请与权限」是统一演示场景，新增的流程和能力均为设计目标。

### 页面与公共组件的边界

外层只保留当前 Fouc 的项目选择、主导航和系统栏。工作台承载当前项目的工作入口；任务保留实际任务处理；资产将来投影权威产物引用；智能体继续管理设备上的实际 Agent。工作项、设计、审阅等深层工作面通过现有系统页签与历史打开。页面中的活动目录、文件树、依赖索引只导航当前对象，不成为第二套应用导航。

一个页面只承担一种主要工作。需求页处理目标、疑问和验收标准；设计页处理正式方案；规划页处理任务、依赖和上下文包；执行页处理当前任务及结果；审阅页处理一次具体的交付与确认；集成页处理合入、环境和真实端到端验证。项目总体信息、完整聊天、所有历史与全量日志不常驻每个页面，通过引用、就地评注或一次只开一个的辅助面板进入。

| 内容 | 默认呈现 | 深入方式 |
| --- | --- | --- |
| 当前工作项和主要动作 | 一行紧凑对象工具栏 | 标题旁菜单查看负责人、活动路线和属性 |
| 十项活动 | 当前活动名称，或当前对象的单一活动索引 | 展开可选活动；沿用、插入和返工记录有原因 |
| 与 Agent 协作 | 当前段落建议、任务进展或明确待答问题 | 打开协作面板；结果吸收进权威产物 |
| 任务上下文包 | 当前任务的范围和关键停止条件 | 展开目标、仓库、分支、文件、验证方式和停止条件 |
| Gate | 当前真正需要处理的一次确认 | 打开与具体版本绑定的证据与确认页 |
| 完整日志、历史和方法配置 | 收起 | 从相关对象打开，不挤占正常工作的首屏 |

### 十项活动的完整软件落点

下表定义五个候选方向共同需要承载的能力，并不要求每个方向显示相同的十个菜单。

| ADD 活动 | 软件中的主要工作面与结果 |
| --- | --- |
| 1 业务需求收集与澄清 | 目标、用户、范围、待澄清问题、用户故事和可观察的验收标准；讨论结论进入需求正文 |
| 2 项目架构设计 | 项目级架构与模块职责、部署和交互关系；工作项引用已有方案或提出明确修订 |
| 3 架构决策记录 | 独立 ADR，比较选项、理由、影响和决定；可从任意活动插入 |
| 4 特性边界讨论 | 本次负责范围、排除范围、所有者、消费者和交接契约，形成边界正文 |
| 5 特性详细设计 | 流程、接口、数据、异常、安全及故事；正式设计正文与就地评注 |
| 6 任务拆解与批次规划 | 任务清单、依赖批次、文件范围、验收命令和测试计划；测试设计在此开始 |
| 7 编码实施与局部测试 | 可重复的失败证据、当前任务实现、真实 diff、局部验证和项目检查结果 |
| 8 独立评审与修复复审 | 独立 Reviewer 的问题、修复与复审轮次、对应提交和结论 |
| 9 集成发布与端到端验证 | 分支集成、合入、发布批准与发布记录；部署后另做真实用户旅程 E2E |
| 10 知识整理与沉淀 | 回写原权威设计、索引、规则与 Skill 的具体修改；不恢复知识库模块 |

### 证据、确认与返工

Gate 是一次与版本绑定的检查，不增加第十一类活动。G0 检查材料与影响范围；G1 检查任务、依赖与文件范围；G2 检查具体任务实施方案；G3 检查实施后的 diff 与验证；G4-task、G4-batch 分别检查独立的任务评审与批次评审；G5 检查集成合入并确认。设计文档的业务确认不能随意命名为 G2；构建成功和 G5 合入确认也不能冒充真实 E2E 通过。

确认页面明确显示对象、产物或提交版本、证据、确认人、尚缺内容以及确认后的动作。缺少证据时直接定位缺项；没有操作权限时显示实际负责人及等待原因。上游设计或提交变化使关联确认进入「需复核」，保留当时的确认记录，并说明变化来源。用户送回时定位具体问题，生成可执行修复事项；修复后复审，不能在原绿色勾选上静默覆盖。

Agent 负责起草、实现、验证和预审；负责人决定目标、架构取舍、风险接受和发布批准。实施作者的自检、Lead 的 G3 检查、Reviewer 的独立评审分别记录。停止运行、执行失败、设备未就绪与缺少权限都在当前任务内提供恢复入口，不清除产物草稿、不把未执行结果显示为成功。

### 阶段工作室：当前活动决定工具

这套让用户先进入一个工作项，再回到正在进行的活动。当前活动占据主工作面，任务规划和独立审阅使用各自专门的布局。适合从一个明确需求持续推进到交付、希望知道「我现在该做什么」的人。

```text
工作台 · 工作项列表
└─ 一个工作项
   ├─ 活动工作面：需求 / 项目架构 / ADR / 边界 / 详细设计
   ├─ 批次规划 → 任务执行
   ├─ 独立评审 → 修复 → 复审
   └─ 集成与 E2E → 回写权威资料
```

需求、架构、ADR、边界和设计用当前工作项内的窄活动索引切换，正文编辑器随活动变化。活动索引可以收起，规划与审阅页面直接把宽度还给任务依赖或代码。已有架构按引用沿用，ADR 可插入；索引不连接成固定步骤，不显示「5/10」。新建工作项只先询问目标和类型，必要信息在相应活动内逐步补齐。

代表路径是：创建新需求，答复 Lead 整理的疑问并确认验收目标；在设计工作面与下游开发/测试协作；切换批次规划，检查任务范围和依赖；Agent 按上下文包执行；Lead 检查后交独立 Reviewer；修复复审后进入集成和真实 E2E；最后回写原设计和规则。边界发生变化可退回边界讨论，受影响的设计、任务和评审标为需复核。

本方向用精密编辑器的排版、窄索引和就地评注建立质感。它的代价是活动目录容易被误读为瀑布流程，必须在活动的可选、沿用和返工状态上表达清楚；同时处理许多工作项时仍要回到项目列表，当前设计页不兼任项目总控台。

### 成果工坊：围绕权威产物工作

这套把可验证、可引用的正式成果作为主对象。活动说明当前在做什么；用户日常操作的是一份需求、一项决定、一份设计或一组证据。适合重视方案质量、正式交接和长期可追溯性的团队。

```text
工作台 · 交付目录
└─ 一个工作项的成果索引
   ├─ 正文编辑室：需求 / 架构引用 / ADR / 边界 / 设计与故事
   ├─ 任务与测试计划 → 任务执行
   ├─ 实施证据审阅 → 独立评审与复审
   └─ 交付记录 → 发布 / E2E / 资料回写
```

成果索引用「定义与决策、方案与执行、交付」等分组归拢文件行；状态、负责人和修订时间是列，避免十张阶段卡。选中行可轻预览，真正编辑时打开独立正文工作面。正文占主要宽度，成果树只浏览本工作项；评注和 Agent 建议一次展开一种，旁注与选中段落对齐。正文是唯一权威来源，索引、聊天、审阅和资产投影只引用它。

代表路径是：交付目录创建目标，Lead 澄清并形成需求草稿；负责人确认后补齐必要的边界、ADR 和设计；从计划生成关联任务和上下文包；实施完成后打开 G3 证据审阅，把验收目标、diff 和验证对应；通过后交独立 Reviewer 执行 G4-task 与复审；完成批次检查、集成与 E2E；在交付记录中处理需回写的权威资料。明确的小 Bug 直接从复现证据进入实施，不补一整套无用文档。

本方向的质感来自编辑出版物式的正文、精细表格、内联引用和轻量评注。它的代价是短小的纯执行任务可能多一次打开产物的动作，应允许直接继续当前任务；成果索引也不能膨胀成按目录找文件的管理工具，默认突出需要继续处理的内容。

### 协作调度台：从需要我判断的事项进入

这套为同时推进多个工作项的人设计。工作台首先回答「现在什么需要我决定、审阅或接手」，执行进展留在任务批次，判断进入专属交接审阅。适合 Lead 与多人、多 Agent 并行，不以一屏运行指标代替协作。

```text
工作台 · 待我处理
├─ 决定 / 审阅 / 接手事项 → 对应的具体工作项与成果
├─ 任务 · 当前批次 → 任务执行与上下文包
├─ 交接审阅 → 修复与复审
└─ 集成交付 → 发布 / E2E / 资料回写
```

收件箱以连续行分组，显示事项、所属工作项、当前活动、来源和更新时间。选中行只显示与这次判断相关的摘要和未决问题，正式放行进入具体版本的审阅页。阶段、角色、执行状态分别表达；十活动只在工作项的活动选择器展开。批次页只展开当前批次，依赖未满足的任务等待；无依赖且文件范围不冲突的任务可以并行。

代表路径是：新需求先完成澄清，或从报告问题进入复现；Lead 配置相关产物和任务上下文；负责人在待处理队列确认目标、架构取舍和关键边界；就绪任务在当前批次执行；Lead 检查结果后进入独立审阅；Reviewer 送回的问题形成修复事项，复审保留历史轮次；集成、发布和真实 E2E 单独验证，再整理长期资料。一个事项处理后从待处理队列移出，处理历史仍能按工作项追溯。

本方向通过紧凑表格、精确状态和一份清楚的交接建立专业感。它的代价是新手需要理解「待我处理」与「正在执行」的差别；空项目应给出创建第一项工作的入口，不能先展示空队列和一堆运行数量。待处理属于工作台内容，不新增全局 Inbox、自动化模块或第二套侧栏。

### 依赖地图：围绕关系和变化影响工作

这套从「谁提供什么、谁依赖它、改动会影响哪里」进入。它把 ADD 的边界、上下文、并行条件和交付证据转成可浏览的工作对象关系，适合跨模块、接口消费者较多或需要理解影响范围的交付。

```text
工作台 · 工作项目录
└─ 一个工作项的依赖地图
   ├─ 目标 / 架构 / ADR / 边界 / 设计的关联正文
   ├─ 契约与责任对齐
   ├─ 任务依赖与批次 → 当前任务执行
   ├─ 独立评审 → 修复与复审
   └─ 集成与真实 E2E → 权威资料回写
```

地图只呈现当前工作项中有意义的一小组目标、契约、实现和证据对象。关系表达引用、依赖、生产与消费，不把十活动画成十个必经节点。选中节点可以看准备度和一项主要动作；双击或打开进入独立正文、任务或审阅工作面。地图本身不承载完整文档、diff 和长日志，也不引入已移除的自动化流程编排模块。

代表路径是：从目标建立必要的边界和架构引用，在契约页对齐所有者、消费者和验收责任；设计拆出任务后，地图呈现可并行与被阻塞的对象；从任务进入实施与独立评审；回到地图确认依赖准备度后，进入集成和真实用户旅程验证。契约变更时高亮直接消费者及需复核的任务与证据，点击即可进入对应工作面处理，避免所有节点一律失效。

本方向采用清晰的白色技术画布、细关系线、紧凑节点和少量语义状态，选中对象的细节只在局部出现。它的优势是责任、阻塞与影响直观；代价是简单需求用图可能比列表慢，初始默认聚焦当前目标与一层直接依赖，完整关系按需展开，不把图规模当成功能价值。

### 决策案卷：让一次交付的判断脉络可读

这套围绕一个工作项的判断与版本演进组织体验：目标怎样确定、有哪些约束、为什么选这个方案、交付结果如何证明。它适合需要负责人反复权衡、异步接手，或者在一段时间后仍要理解决定来由的工作。

```text
工作台 · 工作项案卷目录
└─ 一个工作项的当前案卷
   ├─ 需求澄清 → 需求与验收正文
   ├─ 架构 / 边界 / 详细设计的专属工作面
   ├─ 随时插入 ADR 决策室 → 返回原活动
   ├─ 任务规划 → 实施 → 独立评审与复审
   └─ 交付确认 → 回写权威资料并收束本次执行记录
```

案卷以精简的判断、版本与交接脉络呈现一次交付，突出当前待决定事项；完整执行日志和全部聊天保留在相关对象中，案卷不成为无限聊天流。每条记录引用当时的正式产物与证据，点击打开专用页面。ADR 决策室横向对齐候选方案、约束、依据与影响，负责人的决定回写唯一 ADR，并返回发起这次取舍的活动。

代表路径是：澄清目标后将必要结论吸收进需求正文；边界和设计出现关键取舍时插入 ADR，对齐候选方案与证据；负责人决定后回到设计和规划；按任务上下文实施、验证与独立评审；交付确认分别核对合入、发布批准和真实 E2E；最后审阅需回写的文档、规则与技能修改。发现新问题时在同一案卷继续活动，旧决定保留原版本依据，当前状态明确标出需重新确认。

本方向用连续的时间脉络、紧凑比较表和精细编辑排版建立质感。它的优势是异步接手和「为什么」清楚；代价是高频操作如果都回到案卷会绕路，所以设计、任务和审阅均可直接继续，案卷负责上下文和判断，不替代各活动工具。

### 如何比较五套方案

这五套是信息架构的候选，不要求把五套主入口同时塞进产品。选型先确定用户每天从什么对象进入，再复用其他方向中合适的局部工具。界面外壳、产物权威来源、上下文包和证据规则保持一致。

| 候选 | 用户先看什么 | 最适合的工作 | 主要代价 |
| --- | --- | --- | --- |
| 阶段工作室 | 当前活动与正在编辑的内容 | 从单个需求持续推进到交付 | 活动索引可能被误读为线性流程 |
| 成果工坊 | 正式成果与需继续处理的正文 | 方案质量、正式交接、长期追溯 | 小任务可能多一次打开成果的动作 |
| 协作调度台 | 需要我决定、审阅或接手的事项 | 多工作项、多人与 Agent 并行 | 初次使用需要理解队列与执行的关系 |
| 依赖地图 | 责任、依赖和变化影响 | 跨模块与契约协作、集成验证 | 简单工作用图可能比列表慢 |
| 决策案卷 | 当前判断及其演进依据 | 高频取舍、异步接手、理解决定来由 | 高频执行需要直达活动以免绕路 |

初步建议优先验证「阶段工作室」的主路径：工作项 → 当前活动 → 专属工作面。需求与设计采用「成果工坊」的连续正文和就地评注，任务实施与审阅采用各自的专用页面。待实际出现多工作项并行的管理需求，再将「待我处理」作为工作台的内容视图；关系图和案卷可以作为工作项的按需视图。此建议尚未构成选型，不自动扩大当前实现范围。
