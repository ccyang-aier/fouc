# 本地 Agent 发现与纳管设计

## 一、目标

本地 Agent 管理是 Fouc 的零号基础设施。其目标不是包装几个 CLI 按钮，而是建立稳定的本地 Agent 控制面：自动发现用户已经安装的 Agent，理解其能力与状态，安全地下发操作，并把不同 Agent 的运行过程转换为 Fouc 可以编排、观察和审计的统一语义。

V1 首批纳管对象：

- Codex CLI；
- Claude Code CLI；
- OpenCode CLI。

后续新增 Agent 时，应主要增加 Driver 与能力映射，不修改 Work Room、工作流和证据模型。

## 二、为什么必须先做

Fouc 明确不自研 Coding Agent。用户机器上的 Agent 因而不是外部附加能力，而是 Fouc 的核心执行引擎。

如果 Fouc 只能让用户手工配置一条命令：

- 无法确认命令对应什么 Agent、版本是否兼容、当前是否可用；
- 无法可靠创建、恢复、取消和终止会话；
- 无法统一接收流式输出、工具调用、审批请求、变更和错误；
- 无法把权限、工作目录、任务和执行记录绑定起来；
- 无法知道某个 Agent 是否支持特定模型、结构化输出或会话恢复；
- 无法为上层工作流提供稳定的失败语义与审计证据。

因此正确的依赖顺序是：

```text
Agent 发现与纳管
        ↓
任务与会话控制
        ↓
多仓工作区 / 远程诊断
        ↓
团队流程 / 审核 / 交付
```

## 三、对象模型

### `AgentProvider`

描述一种 Fouc 支持的 Agent 产品及其 Driver，例如 Codex、Claude Code、OpenCode。它定义识别规则、版本兼容范围、能力映射和启动协议。

### `AgentInstallation`

表示机器上的一个实际安装实例：

- Provider；
- 可执行文件绝对路径；
- 来源，如系统安装、包管理器、便携目录或用户指定；
- 版本与探测时间；
- 健康状态；
- 原生配置位置引用；
- 是否启用、是否由用户确认。

同一种 Agent 可以存在多个安装实例，Fouc 不应假设命令名全局唯一。

### `AgentProfile`

表示用户在某个安装实例上的运行偏好，例如默认模型、权限模式、附加参数、允许使用的环境变量和适用工作空间。Profile 不复制 Agent 原生凭据。

### `CapabilityManifest`

描述某个安装实例在当前版本下真实支持的能力：

- 交互式或非交互式运行；
- 结构化或纯文本事件；
- 流式输出；
- 多轮追加指令；
- 会话 ID 与恢复；
- 工具调用与审批事件；
- 工作目录与多目录访问；
- 模型、推理强度、权限或沙箱控制；
- MCP、Skills、Rules 等扩展入口；
- 取消、优雅停止与强制终止。

能力清单必须由版本探测与 Driver 规则产生，不能只根据 Agent 名称静态假设。

### `AgentSession`

表示可以承载多轮交互的 Agent 会话，关联安装实例、Profile、工作目录、原生会话 ID、创建时间、状态和所属 WorkObject。

### `AgentRun`

表示会话中的一次具体执行，记录任务、输入引用、权限、进程、事件流、结果、退出状态、资源消耗和审计信息。

## 四、自动发现机制

### 发现来源

Fouc 按以下顺序建立候选集：

1. 用户已经确认并保存的安装路径；
2. 当前进程可见的 `PATH`；
3. 操作系统常见应用与用户级可执行目录；
4. 常见包管理器能够解析出的安装位置；
5. 用户手工选择的可执行文件。

发现过程只读取元数据，不遍历无关用户文件，不运行来源不明的候选程序。

### 身份确认

候选程序必须通过 Provider Driver 的探测流程：

1. 规范化并解析最终可执行路径；
2. 校验文件类型和来源信息；
3. 使用无副作用的版本/帮助探测确认身份；
4. 解析版本并匹配 Driver 兼容范围；
5. 运行最小健康检查；
6. 生成能力清单和兼容状态。

不能仅凭文件名将任意 `codex.exe`、`claude.exe` 或 `opencode.exe` 直接视为可信 Agent。

### 状态分类

- `ready`：已识别、版本兼容、可以启动；
- `needs_auth`：程序可用，但原生登录或凭据尚未就绪；
- `incompatible`：已识别，但当前 Driver 不支持该版本；
- `unhealthy`：探测超时、启动失败或输出异常；
- `disabled`：用户主动停止纳管；
- `missing`：此前存在的路径当前不可用。

状态应显示原因与修复入口，不能只展示“不可用”。

## 五、统一 Agent Driver

每一种 Agent 由独立 Driver 适配。上层只能依赖统一接口，Agent 特有能力通过能力清单与扩展字段暴露。

### 基线接口

```text
discover()             发现候选安装
probe(installation)   确认身份、版本、健康和能力
createSession(input)   创建受管会话
send(runInput)         下发任务或追加指令
subscribe(sessionId)   接收标准化事件流
cancel(runId)          取消当前运行
resume(sessionId)      恢复可恢复会话
terminate(sessionId)   结束会话及其子进程
diagnose(sessionId)    获取原始诊断信息
```

### 标准事件

Driver 至少将原生输出转换为以下事件：

- `session.started`；
- `run.started`；
- `message.delta` / `message.completed`；
- `tool.requested` / `tool.started` / `tool.completed`；
- `approval.required` / `approval.resolved`；
- `artifact.changed`；
- `run.completed` / `run.failed` / `run.cancelled`；
- `session.ended`。

原生协议无法提供某类事件时，Driver 必须声明不支持或给出明确降级，不能根据终端文本猜测高风险状态。

### 适配层级

| 层级 | 能力 | 使用方式 |
|---|---|---|
| L0 发现 | 路径、身份、版本、健康 | 只能登记，不能受管运行 |
| L1 进程 | 启动、输出、退出、取消 | 适合一次性无状态任务 |
| L2 会话 | 多轮指令、会话 ID、恢复 | 支持 Work Room 持续协作 |
| L3 结构化控制 | 工具事件、审批、制品、用量 | 支持完整流程编排与审计 |

Fouc UI 必须展示每个安装实例的实际层级。V1 的三种首批 Agent 至少达到 L2；只有达到 L3 的能力才能参与相应的自动审批与证据流程。

## 六、进程与会话管理

Fouc 在桌面端维护本地 Agent Supervisor，负责：

- 以明确的工作目录和环境变量白名单启动子进程；
- 分配进程、会话与 Run ID，维护父子关系；
- 流式读取标准输出、标准错误和结构化事件；
- 控制并发数、排队、超时和资源租约；
- 支持优雅取消，超时后再允许用户强制终止；
- Fouc 重启后识别可恢复会话与遗留进程；
- 防止不同 WorkObject 的输入、输出和工作目录串线；
- 保存必要日志并执行大小、期限与敏感数据策略。

“停止显示输出”不等于“进程已经停止”。UI 必须区分运行中、等待输入、等待审批、取消中、已结束、失联和失败。

## 七、可下发操作

### 安装级操作

- 刷新发现与健康检查；
- 启用或停用纳管；
- 选择默认安装实例；
- 打开原生配置或原生终端；
- 查看版本、路径、能力和兼容问题；
- 由用户明确发起安装、升级或卸载。

### Profile 级操作

- 设置默认模型、权限模式和附加参数；
- 设置允许访问的工作空间；
- 配置环境变量白名单与非敏感运行参数；
- 设置并发、超时和资源限制；
- 选择是否继承 Agent 原生项目规则和扩展。

### 会话与运行级操作

- 创建会话并绑定 WorkObject 与工作目录；
- 下发任务合同、文件/制品引用和远程环境快照；
- 追加指令、回答 Agent 问题或处理审批；
- 暂停调度、取消运行、恢复会话或终止进程；
- 查看原始输出、标准事件、文件变更和错误；
- 将结果交给其他受管 Agent 或人类继续处理。

Fouc 只允许下发 Driver 和 CapabilityManifest 明确支持的操作。

## 八、凭据与配置边界

- 默认复用 Agent 自己的登录状态和凭据存储，Fouc 不读取或复制长期 Secret；
- 需要登录时，Fouc 引导用户进入 Agent 的原生认证流程；
- 传给子进程的环境变量使用显式白名单，敏感值不进入任务记录；
- 修改 Agent 原生配置前展示 Diff，并要求用户确认；
- Fouc Profile 只保存覆盖项和引用，不生成第二份完整原生配置；
- 企业策略可以禁止特定 Agent、版本、模型、权限模式或数据域组合；
- 升级与卸载属于显式、可见操作，不能作为后台健康修复自动执行。

## 九、主要界面

### Agent 资产页

按 Provider 和安装实例展示：名称、版本、路径、状态、适配层级、默认 Profile、最近使用时间和问题提示。提供刷新、添加路径、设为默认、诊断和解除纳管操作。

### Agent 详情页

展示能力清单、Profiles、原生配置引用、活动会话、历史运行、兼容性与诊断信息。

### Work Room 执行器选择

创建任务时默认推荐满足能力、权限和工作空间约束的 Agent。用户可以手工切换，并看到差异与降级影响。

### 运行控制区

持续显示当前阶段、Agent、会话、工作目录、权限、运行时间、事件、审批和取消/接管入口。

## 十、失败与恢复

- 找不到已登记路径：标记 `missing`，保留历史引用，不自动删除；
- 版本不兼容：禁止危险控制，只保留诊断与原生终端入口；
- 启动失败：记录命令、工作目录、退出码和经过脱敏的错误；
- Agent 崩溃：Run 标记失败，保留工作区和已有制品；
- Fouc 崩溃：重启后核对原生会话和进程，不盲目重跑任务；
- 输出协议变化：停止结构化自动操作，降级或标记不兼容；
- 取消超时：提示进程仍可能运行，由用户决定是否强制终止；
- 会话无法恢复：创建新会话时显式生成上下文交接包。

## 十一、V1 范围

### 必须实现

- 自动发现 Codex CLI、Claude Code CLI 和 OpenCode CLI；
- 安装实例、Profile、能力、会话和运行的完整对象模型；
- 三种 Agent 的 L2 基线纳管；
- 至少对支持结构化控制的 Agent 实现其真实 L3 能力；
- 统一任务下发、流式事件、追加指令、取消、终止与诊断；
- Work Room、权限、工作目录与 AgentRun 的强关联；
- 可解释的能力差异与降级；
- 进程隔离、凭据边界和完整审计。

### 暂不实现

- 静默安装、自动升级或自动卸载 Agent；
- 对所有 Agent 强行提供相同高级功能；
- 读取或迁移 Agent 的长期登录凭据；
- 依赖 UI 屏幕抓取模拟稳定控制协议；
- 在 V1 建设远程 Agent 市场或开放式 Agent Mesh；
- 自研 Agent 推理循环替代已纳管执行器。

## 十二、验收场景

1. 用户机器只安装了 OpenCode：Fouc 启动后自动识别，展示版本和能力，用户可直接创建会话并下发任务；
2. 同时安装多个 Codex 版本：Fouc 分别登记，允许用户选择默认实例，不混淆路径与会话；
3. Claude Code 尚未登录：Fouc 标记 `needs_auth`，引导原生认证，而不是索取或保存密钥；
4. Agent 执行中请求高风险工具：Fouc 在 Work Room 展示审批，未批准前不推进对应流程；
5. 用户取消长任务：Fouc 先请求优雅取消，确认实际进程状态，并保留已有输出与变更；
6. Agent 升级导致事件格式变化：Driver 将其标记为不兼容或降级，不把未知输出误判为成功；
7. Fouc 重启：能够恢复可恢复会话，或明确给出不可恢复原因和上下文交接方案。
