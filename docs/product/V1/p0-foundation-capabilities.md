# Fouc V1 P0 基础能力

## 一、文档目的

本文件定义 Fouc V1 能够成立所必须具备的平台底座。它们不一定都是用户直接感知的独立功能，但缺少其中任何一项，两个或更多上层特性将无法可靠运行，或者只能形成不可恢复、不可审计、不适合团队使用的演示。

P0 基础能力与核心特性的区别：

- **基础能力**回答“Fouc 凭什么能够安全、稳定地执行工作”；
- **核心特性**回答“用户可以用这些能力完成什么工作”；
- 核心特性不能通过绕过基础能力的临时实现标记为完成；
- 文档、静态界面或一次成功演示不代表基础能力已经完成。

## 二、P0 判定标准

一项能力满足以下任意两条，即应作为 P0 基础能力管理：

1. 被两个或更多 V1 核心特性共同依赖；
2. 缺失后会破坏权限、数据、代码或执行状态的完整性；
3. 后补会迫使领域模型、执行协议或数据存储发生大规模重写；
4. 决定任务能否暂停、恢复、转交、审核或追溯；
5. 决定桌面端、Web 端、人员与 Agent 能否共享一致的工作事实。

P0 表示 V1 必须实现其最小闭环，不表示一次性建设完整企业平台。每项能力都应严格遵守本文定义的 V1 边界。

## 三、基础能力总览

| ID | 基础能力 | 状态 | 主要支撑对象 |
|---|---|---|---|
| F0 | 本机能力与 Agent 控制面 | 未完成 | 所有需要 Agent 执行的任务 |
| F1 | 本地安全执行内核 | 未完成 | Agent、命令、脚本与本地工具执行 |
| F2 | 项目、代码仓与隔离工作区控制面 | 未完成 | 多仓分析、代码修改与 Git 交付 |
| F3 | 身份、凭据、委托与策略中心 | 未完成 | 本地、远程、团队与高风险操作 |
| F4 | 持久化工作运行时与事件存储 | 未完成 | Work Room、工作流、Session 与 Run |
| F5 | 上下文、制品与证据基础设施 | 未完成 | Agent 输入、审核、验证与交付 |
| F6 | 连接器控制面 | 未完成 | Git/CodeHub、远程环境、问题系统与 CI |
| F7 | 团队 Workspace、同步与通知 | 未完成 | 多角色协作、审核、转交与 Web 访问 |

状态统一使用以下语义：

- `未完成`：尚未达到最小可用闭环；
- `进行中`：已经开始实现，但退出标准未全部通过；
- `完成`：实现、自动化测试和验收场景均通过；
- `阻塞`：存在明确外部依赖，当前无法继续。

## 四、F0：本机能力与 Agent 控制面

### 定义

发现并纳管用户机器上已有的 Agent 与必要执行工具，使 Fouc 能够确定“有哪些执行能力、在哪里、什么版本、当前是否可用、允许做什么”。

### 职责边界

- 发现 Codex CLI、Claude Code CLI、OpenCode CLI 等 Agent；
- 识别可执行文件真实路径、来源、版本、健康和登录状态；
- 管理 AgentProvider、AgentInstallation、AgentProfile 与 CapabilityManifest；
- 通过 Agent Driver 统一创建会话、下发任务、追加指令、取消和终止；
- 展示真实能力差异，不伪造不受支持的高级操作；
- 发现 Git、Shell、SSH 等完成 V1 任务所需的基本宿主能力；
- 允许用户启用、停用、选择默认实例或打开原生工具；
- 不负责复制长期凭据，也不静默安装、升级或卸载 Agent。

Agent 纳管的详细协议见 [本机 Agent 设计](./design/agents/fouc-agent-management-design.md)。

### V1 最小实现

- 自动发现本机已有的 Codex CLI、Claude Code CLI 和 OpenCode CLI；
- 三类 Agent 均达到 L2 会话级纳管；
- 至少对真实支持结构化控制的 Agent 暴露其 L3 能力；
- 建立 Agent 资产页、能力页、健康诊断与运行入口；
- 将每个 AgentSession 和 AgentRun 绑定到安装实例、用户、WorkObject 和工作目录。

### 退出标准

- 已安装的首批 Agent 能被准确发现，不存在仅凭同名文件误识别的情况；
- 用户无需在 Fouc 中重新配置模型凭据即可启动受管会话；
- 创建、发送、追加、取消和终止操作具有确定状态；
- Agent 崩溃、退出或协议不兼容能够被识别并保留诊断信息；
- 能力差异和降级对用户可见且可解释。

## 五、F1：本地安全执行内核

### 定义

为 Agent Driver、命令、脚本和本地工具提供统一、受控、可观察的执行环境。Agent Driver 不直接各自实现一套操作系统进程管理。

### 职责边界

- 统一管理进程、标准输入输出、标准错误和 PTY；
- 设置工作目录、环境变量白名单、命令参数与执行身份；
- 管理队列、并发、超时、资源租约和子进程关系；
- 提供启动、流式输出、等待输入、优雅取消和强制终止；
- 区分“UI 停止显示”“任务请求取消”和“进程实际结束”；
- Fouc 重启后识别遗留进程，不盲目重复执行；
- 封装 Windows、macOS 与 Linux 的平台差异；
- 将执行事件交给持久化运行时，不承担业务工作流决策。

### V1 最小实现

- 支持当前 V1 主目标平台上的进程与 PTY 管理；
- 实现标准 CommandSpec、ExecutionHandle、ExecutionEvent 与 ExitResult；
- 支持流式输出、超时、取消、强制终止和子进程回收；
- 执行前固定工作目录、环境变量和权限；
- 记录经过脱敏的命令、时间、退出状态与错误；
- 其他目标平台未完成时必须明确标记，不隐式宣称支持。

### 退出标准

- 同一执行请求不会因重试产生两个不受管进程；
- 取消后可以确认进程是否真正结束；
- Fouc 异常退出后能够识别并处理遗留进程；
- 不同 WorkObject 的输入、输出和工作目录不会串线；
- Agent Driver 和本地工具均通过同一执行内核运行。

## 六、F2：项目、代码仓与隔离工作区控制面

### 定义

发现、登记并管理 Agent 将要操作的项目与代码仓，建立本地仓库、公司版本仓、个人 Fork、服务和环境部署版本之间的准确关系。

### 职责边界

- 自动扫描或由用户登记本地 Git 仓库；
- 识别 Origin、Upstream、个人 Fork、默认分支和当前分支；
- 记录 Service、RepositoryBinding、Commit、Tag 和构建版本关系；
- 展示 dirty 状态、未推送提交、分支偏离和远程连通性；
- 根据目标环境版本选择正确的代码分析基线；
- 为任务创建、租用、锁定和回收隔离 worktree；
- 管理跨仓 ChangeSet、仓库依赖与变更顺序；
- 不替代 Git 或 CodeHub 作为代码和提交的权威来源。

### V1 最小实现

- 支持本地 Git 仓库发现与手工登记；
- 支持公司版本仓、个人 Fork 和本地目录的映射；
- 支持服务与仓库、环境部署版本与 Commit 的绑定；
- 每个修改任务使用独立 worktree 或等价隔离工作区；
- 至少支持一个 Issue 关联多个微服务仓；
- 推送与创建合并请求前展示目标远端、分支与 Diff。

### 退出标准

- Fouc 能回答“Agent 正在修改哪个仓库、哪个 Commit、哪个隔离工作区”；
- 用户当前工作目录中的未提交修改不会被任务隐式污染；
- 环境版本与本地代码版本不一致时必须显式提示；
- 两个任务不能无约束地同时租用同一可写工作区；
- 隔离工作区异常退出后可恢复或安全回收。

## 七、F3：身份、凭据、委托与策略中心

### 定义

统一表达“谁请求、谁负责、哪个 Agent 以什么身份、在什么范围、因何授权执行什么动作”，并安全管理访问外部系统所需的凭据引用。

### 职责边界

- 管理用户、团队、Agent、Connector 和服务身份；
- 管理 Workspace 成员、角色与资源访问范围；
- 使用 Delegation 固定请求人、责任人、执行者、用途、作用域和有效期；
- 按风险划分只读、本地修改、远程写入、推送、合并与发布操作；
- 使用操作系统安全存储或企业凭据系统保存 Secret，业务数据只保存引用；
- 支持短期凭据、吊销、审批和最小权限；
- 将策略决定与 Agent 提示词分离；
- 为每次高风险操作生成可审计的授权记录。

### V1 最小实现

- 支持个人身份、最小团队成员与角色模型；
- 支持本地安全凭据存储和外部凭据引用；
- 建立 read、modify-local、write-remote、push、release 风险等级；
- 任务创建时生成明确的 Delegation；
- 高风险动作在执行前要求与动作匹配的显式授权；
- 授权取消后阻止尚未开始的动作，并处理正在运行的动作。

### 退出标准

- 任一 AgentRun 都能回答请求人、责任人、Agent、实际身份和授权来源；
- 未授权的远程写入、推送和发布无法执行；
- 长期凭据不会出现在 Prompt、日志、事件或制品正文中；
- 权限检查由确定性策略执行，不能被提示词绕过；
- 凭据失效、吊销或权限不足具有明确错误语义。

## 八、F4：持久化工作运行时与事件存储

### 定义

为 WorkObject、Workflow、TaskContract、AgentSession、AgentRun、审批和外部事件提供持久状态、确定性生命周期与恢复能力。

### 职责边界

- 持久化工作对象、任务、会话、运行、流程和审批状态；
- 使用追加式事件记录重要状态变化；
- 定义合法状态转换、进入条件、退出条件和失败语义；
- 为外部调用、重试和状态推进提供幂等键；
- 支持排队、运行、等待输入、等待审批、暂停、取消、失败和完成；
- Fouc 重启后从持久事实恢复，而不是从 UI 内存猜测状态；
- 识别失联 Session、Run、Connector 调用和孤儿任务；
- 不存储模型隐式思维链，只保存计划、结论、事件和制品引用。

### V1 最小实现

- 固化 WorkObject、WorkflowInstance、TaskContract、AgentSession 与 AgentRun 状态机；
- 建立带序号、时间、主体和关联对象的事件日志；
- 支持任务暂停、等待、恢复、取消、重试和人工接管；
- 为 Git 推送、远程写入等不可重复动作提供幂等保护；
- 桌面端重启后恢复未完成任务或明确标记无法恢复原因；
- 提供单个 Work Room 的完整时间线。

### 退出标准

- 重启应用不会把运行中任务错误标记为成功或直接丢失；
- 重试不会重复创建分支、重复推送或重复执行远程写操作；
- 每次状态变化都能追溯触发者、前置状态、依据和结果；
- 非法状态跳转被确定性拒绝；
- UI 状态可以由持久对象与事件重建。

## 九、F5：上下文、制品与证据基础设施

### 定义

从权威来源组装任务所需的最小 Context Pack，并统一管理 Agent 使用或产生的 Artifact 与 Evidence，使输入和结果具备来源、版本与可验证性。

### 职责边界

- 管理代码、问题单、文档、日志、环境快照和用户输入的引用；
- 为每份上下文记录来源、版本、时间、权限、完整性和脱敏状态；
- 按任务目标、Agent 能力和上下文预算选择、裁剪与组织内容；
- 识别过期、版本错配、缺失或不完整上下文；
- 管理补丁、Diff、报告、测试结果、日志片段和审批等制品；
- 使用内容摘要或版本固定重要证据；
- 定义保留期限、大小限制、敏感信息与访问策略；
- 不复制外部系统的全部正文，不在 V1 建设通用知识图谱。

### V1 最小实现

- 实现 ContextRef、ContextPack、Artifact 与 Evidence 对象；
- 支持源码、问题描述、环境快照和验证结果四类核心来源；
- 在进入 Agent 前执行来源检查、版本固定、裁剪和敏感数据处理；
- 将每个 Agent 结论绑定到可复核的上下文与制品引用；
- 支持 Diff、测试结果和远程验证证据的审核视图；
- 关闭 Issue 前检查必要证据是否完整。

### 退出标准

- 任一关键结论都能追溯到具体来源和版本；
- 环境快照与代码版本错配不会被静默忽略；
- Secret 与受限字段在进入模型上下文前得到处理；
- 大体量日志不会未经筛选全部传给 Agent；
- 被用于关闭问题的证据无法被后续内容静默覆盖。

## 十、F6：连接器控制面

### 定义

用统一生命周期纳管 Git/CodeHub、远程环境、问题系统、CI/CD、文档和可观测平台连接，使业务流程不直接耦合每个外部系统的私有接口。

### 职责边界

- 定义 ConnectorProvider、ConnectorInstance 与 ConnectorCapability；
- 管理连接实例、认证引用、健康、能力、版本和作用域；
- 提供统一的 Invoke、Result、Error、Cancel 与 Diagnose 语义；
- 将只读查询与有副作用动作明确区分；
- 支持连接测试、启用、停用、重新认证和诊断；
- 为外部操作生成调用记录和证据引用；
- MCP 可以作为一种接入协议，但不替代连接器生命周期与治理；
- 外部系统继续拥有其业务事实，Fouc 只保存必要引用和快照。

### V1 最小实现

- Git 与个人 Fork/公司版本仓连接；
- 至少一种测试环境连接方式，如 SSH、WinRM 或 Kubernetes API；
- 一个问题系统的最小导入与状态回填能力；
- CI 或本地验证结果的统一接入；
- 所有连接实例具有健康状态、能力范围和认证状态；
- 远程写入和外部状态变更经过 F3 策略与授权。

### 退出标准

- 连接失败、认证失败、权限不足和外部系统错误可被明确区分；
- 同一业务流程不直接拼接特定系统的认证与请求逻辑；
- 连接器不可用时任务进入可恢复状态，不被误标为完成；
- 外部写操作具有幂等保护和完整审计；
- 更换同类连接器不要求重写 WorkObject 与工作流领域模型。

## 十一、F7：团队 Workspace、同步与通知

### 定义

让桌面端执行者、Web 端协作者和不同角色围绕同一个 WorkObject 共享权威状态，支持审核、转交、等待与通知。

### 职责边界

- 管理个人 Workspace、团队 Workspace、成员与角色；
- 定义哪些状态属于本地执行事实，哪些状态由团队服务持有；
- 将桌面 AgentRun 的必要状态、制品和事件同步给团队；
- 提供审核收件箱、待办、转交、退回与通知；
- 处理多人并发操作、版本冲突和失效审批；
- 根据 F3 权限过滤环境、代码、日志和客户信息；
- 支持离线后重连与同步失败提示；
- V1 不要求完整企业组织树、复杂 SSO 或通用实时协作文档。

### V1 最小实现

- 支持用户、团队 Workspace、成员和最小角色模型；
- WorkObject 与 WorkflowInstance 拥有团队权威状态；
- 桌面端可以发布 AgentRun 状态、待审批项和必要制品；
- Web/桌面端均能查看当前阶段、责任人和下一动作；
- 支持审核收件箱、站内通知和状态变化提醒；
- 支持断线重连、版本检查和冲突提示。

### 退出标准

- 测试、测试经理、研发和审核人能围绕同一个 Issue 完成角色流转；
- 两个客户端不会通过最后写入覆盖掉对方的关键审批；
- 审批只对其查看过的制品版本生效，制品变化后旧审批失效；
- 无权限成员无法通过同步事件获得受限内容；
- 待处理事项能够送达正确角色，并记录确认与处理结果。

## 十二、依赖关系

```text
F3 身份、凭据、委托与策略
 ├── F0 本机能力与 Agent 控制面 ──┐
 ├── F1 本地安全执行内核 ─────────┤
 ├── F2 项目、代码仓与工作区 ─────┤
 └── F6 连接器控制面 ─────────────┤
                                     ▼
F4 持久化工作运行时与事件存储 ──> F5 上下文、制品与证据
                                     │
                                     ▼
                           F7 团队同步与通知
                                     │
                                     ▼
                    Work Room 与 V1 场景特性
```

实现顺序不必完全串行，但以下约束必须成立：

- F0 Agent 纳管必须建立在 F1 执行内核之上；
- F2、F6 的有副作用动作必须经过 F3；
- F0、F1、F2、F6 的运行状态必须写入 F4；
- 上层 Agent 与工作流只能消费 F5 组装的上下文和制品引用；
- 团队协作通过 F7 共享 F4/F5 的权威状态，不直接控制未授权本地进程。

## 十三、核心特性依赖映射

| V1 核心特性 | 必需的 P0 基础能力 |
|---|---|
| 本机 Agent 自动发现与统一纳管 | F0、F1、F3、F4 |
| 统一工作对象与 Work Room | F3、F4、F5、F7 |
| 本地—远程联合诊断 | F0、F1、F3、F4、F5、F6 |
| 多仓隔离工作区与受管 Agent 编排 | F0、F1、F2、F3、F4、F5 |
| 可执行研发流程、验证与交付闭环 | F2、F3、F4、F5、F6、F7 |

核心特性只有在自身验收标准及其依赖的 P0 退出标准同时通过后，才能标记为完成。

## 十四、V1 P0 总体验收门槛

V1 的 P0 基础能力整体完成，至少需要满足：

1. 本机受管 Agent 能在隔离代码工作区中完成一次可取消、可恢复、可审计的任务；
2. 本地与远程操作均经过明确身份、权限和委托检查；
3. 应用重启或连接中断不会丢失任务，也不会重复有副作用动作；
4. Agent 使用的代码、问题和环境上下文具有来源、版本与脱敏记录；
5. Git、测试环境、问题系统和验证结果通过受管连接器进入工作流；
6. 多个角色可以在桌面端和 Web 端围绕同一个 WorkObject 完成审核与转交；
7. 任何标记为完成的工作都具有可复核的制品与证据；
8. 未满足退出标准的基础能力和场景特性不会被界面、文档或演示标记为完成。

## 十五、不属于 V1 P0 的能力

以下能力具有长期价值，但不应扩大 V1 P0 范围：

- Agent 静默安装、自动升级或自动卸载；
- 任意多 Agent Swarm 与自由协商；
- 完整企业 SSO、复杂组织树与跨租户联合身份；
- 可视化无代码流程设计器；
- 通用知识图谱与长期自主记忆；
- Agent、Skill 与 Connector 市场；
- 完整成本运营大盘和组织级资源调度；
- 任意生产环境的自动修改与发布；
- 强行抹平所有 Agent 或外部系统的高级能力差异。
