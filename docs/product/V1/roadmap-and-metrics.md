# Fouc V1 范围、路线与成功指标

V1 路线必须同时推进场景特性与 [P0 基础能力](./p0-foundation-capabilities.md)。任何阶段不得使用绕过 P0 契约的临时实现换取表面闭环。

## 一、V1 范围边界

### 必须做到

- 完成 [P0 基础能力](./p0-foundation-capabilities.md) F0—F7 的 V1 最小闭环与退出标准；
- 自动发现并纳管本机已有的 Codex、Claude Code 和 OpenCode CLI；
- 提供统一的 Agent 能力探测、会话控制、任务下发、取消恢复与审计；
- 深度闭环远程问题定位与修复场景；
- 支持多个微服务仓与环境版本映射；
- 接入现有 Coding Agent，而非自研代码 Agent；
- 实现问题处理角色流、审批、证据和交付包；
- 提供本地优先、远程最小权限的安全模型；
- 用真实团队试点数据验证效率、质量和接受度。

### 明确不做

- 静默安装、升级、卸载 Agent，或迁移 Agent 的长期凭据；
- 全公司所有办公场景的通用门户；
- 自研模型、IDE、代码托管、CI/CD 或可观测系统；
- 无边界的多 Agent Swarm 和 Agent 自由互聊；
- 任意生产环境的全自动修改与发布；
- 可视化无代码流程平台的全部能力；
- 为尚不存在的旧版本数据设计兼容层或迁移路径。

## 二、交付节奏建议

### 阶段 0：执行底座与领域模型（第 1—2 周）

- 建立 F1 本地执行内核的进程、事件、取消与退出结果契约；
- 建立 F3 身份、Delegation、风险等级与凭据引用模型；
- 建立 F4 WorkObject、Session、Run、Workflow 与追加事件存储；
- 定义 AgentProvider、Installation、Profile、Capability、Session 与 Run；
- 定义 Agent Driver、标准事件、能力分级与失败语义；
- 选择 3—5 个真实历史问题完整回放；
- 固化 Issue、环境快照、仓库绑定、任务合同和证据模型；
- 明确角色、门禁、退回与关闭条件；
- 建立当前人工流程的时间与质量基线。

**退出条件**：F1、F3、F4 的最小契约已通过验证；能够解释一次工作将由哪个安装实例、以什么身份、权限和持久状态执行。

### 阶段 1：本地 Agent 纳管闭环（第 3—5 周）

- 完成 F0 本机能力与 Agent 控制面的最小闭环；
- 自动发现 Codex CLI、Claude Code CLI 和 OpenCode CLI；
- 完成身份、版本、健康、登录状态与能力探测；
- 实现统一会话、任务下发、流式事件、追加指令、取消和终止；
- 上线 Agent 资产页、详情页和运行控制区；
- 将 Agent 会话、工作目录、权限与 WorkObject 强关联。

**退出条件**：用户无需在 Fouc 中重新安装 Agent，即可选择本机已有 Agent 完成一次可观察、可取消、可审计的多轮任务。

### 阶段 2：单人联合诊断闭环（第 6—8 周）

- 完成 F2 代码仓与隔离工作区、F5 上下文与证据、F6 连接器控制面的最小闭环；
- 完成本地仓库目录和隔离工作区；
- 接入一种主力测试环境通道；
- 完成环境快照、联合分析、补丁与本地验证。

**退出条件**：研发人员无需向远端复制源码或模型凭据，即可完成一次真实问题的定位与修复。

### 阶段 3：团队流程、证据与试点（第 9—12 周）

- 完成 F7 团队 Workspace、同步与通知的最小闭环；
- 对 F0—F7 执行整体恢复、安全和端到端验收；
- 上线问题状态机、角色、审核收件箱和退回机制；
- 接入问题系统与 Git/CodeHub 的最小闭环；
- 生成根因报告、验证证据和合并请求交付包；
- 支持测试复核与回归关闭。
- 在一个微服务产品团队中连续试点；
- 补齐失败恢复、权限、脱敏、审计与可观测性；
- 根据数据决定下一种 Agent、环境与工作流的接入顺序；
- 输出 V1 评估报告与下一阶段路线。

**退出条件**：一个真实问题能够使用受管 Agent 完成定位、修复、审核与回归，表现出可重复收益且没有突破安全边界。

## 三、成功指标

V1 不以 Agent 调用次数、Token 消耗或生成代码行数衡量成功。

| 维度 | 建议指标 |
|---|---|
| Agent 纳管 | 已安装 Agent 发现成功率、能力探测准确率、会话启动成功率、取消成功率、异常状态识别率 |
| 效率 | 问题上下文准备时间、首次有效根因时间、平均解决时长、跨工具切换次数 |
| 质量 | 首次修复成功率、问题重开率、回归通过率、环境/代码版本错配率 |
| 流程 | 各阶段等待时间、退回次数、超时率、证据完整率 |
| 人类注意力 | 研发主动操作时长、审核阅读时长、需要人工接管的比例 |
| 安全 | 越权动作数、敏感数据泄漏数、长期凭据使用数、未审计远程操作数 |
| 采用 | 周活跃研发数、通过 Fouc 闭环的问题占比、用户继续使用意愿 |
| 经济性 | 单个闭环成本、模型成本、节省的环境准备与重复劳动时间 |

## 四、V1 硬门槛

- 本机已安装的三类首批 Agent 可被准确发现并执行基线纳管操作；
- Agent 原生长期凭据不被 Fouc 复制或持久化；
- 每个 AgentRun 都能关联安装实例、用户、工作对象、目录和权限；
- 远端模型凭据为零；
- 非必要源码复制为零；
- 高风险动作未经批准执行为零；
- 已关闭问题的证据完整率达到 100%。

效率提升目标应在历史问题基线回放后确定，避免使用缺乏事实依据的预设数字。

## 五、试点选择原则

首批问题应覆盖不同难度，但仍满足可安全验证：

- 至少涉及两个微服务仓；
- 需要结合日志、环境版本与源码定位；
- 有明确的历史根因和修复结果可供回放对照；
- 不依赖不可获得的生产数据；
- 可以衡量人工流程耗时与 Fouc 辅助后的变化。
